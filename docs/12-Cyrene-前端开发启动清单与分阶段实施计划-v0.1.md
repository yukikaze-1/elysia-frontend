## 1. 文档目的

本文回答两个问题：

1. 如果现在由我负责开发 Cyrene 前端，正式开工和各阶段联调前还缺哪些资料、资源、权限与产品决策；
2. 这些输入补齐后，按照什么顺序实施、分为几个阶段、每个阶段交付什么以及如何验收。

本文是执行清单，不替代产品需求、通信协议、安全设计和测试方案。后端已经多次迭代，因此前端通过 `BackendAdapter` 适配现有后端，不要求后端为了匹配本文建议字段而重构。

> 本文已有的带日期“状态注记”均为历史快照，不再作为项目当前状态。当前阶段、阻塞项和最新验证只读取 [doc 16](16-Cyrene-前端实施任务清单与进度跟踪.md)。

本文是当前最新的开工和阶段门槛基线；`10-Cyrene-前端实施路线与任务拆分-v0.2.md` 已使用同一套阶段 0～8 编号，并补充技术任务与依赖。若后续出现差异，以本文的进入条件和验收门槛为准，并在同一次变更中同步文档 10。

## 2. 清单使用规则

### 2.1 优先级

| 级别 | 含义 | 处理方式 |
|---|---|---|
| P0 | 阻塞开工或核心联调 | 对应阶段开始前必须补齐 |
| P1 | 不阻塞工程骨架，但阻塞功能完成 | 可先使用 Mock，进入对应阶段前补齐 |
| P2 | 优化项或发布前决策 | 最迟在稳定性或发布阶段补齐 |

### 2.2 完成状态

- `[ ]`：尚未提供或尚未确认；
- `[~]`：已有部分资料，但不足以实现或验收；
- `[x]`：资料已提供，并经过一次读取或运行验证；
- “有接口文档”不等于完成；至少需要一个可验证的真实样例或测试环境结果。

### 2.3 Mock 使用边界

缺少真实接口时可以使用 Mock Backend 推进 UI、状态机和自动测试，但必须遵守：

- Mock 字段与真实字段分离，统一经过 Adapter；
- 使用 Mock 完成的功能标记为“已开发、未联调”；
- 没有通过真实后端验收的阶段不得标记为“已完成”；
- 不在 Vue 组件中写死对后端协议的猜测。

## 3. 最低开工条件

满足以下条件后，可以开始阶段 0 和阶段 1：

- [ ] 已指定前端仓库或允许创建新工程的目录；
- [ ] 已确认代码所有权、目标分支和提交方式；
- [ ] 已确认首要验收平台及最低系统版本；
- [ ] 可以访问至少一个后端测试环境，或取得可重复播放的真实协议样例；
- [ ] 已取得一次完整 AI 流式回复的原始事件记录；
- [ ] 已明确凭据不能写入仓库、普通配置和日志；
- [ ] 已确认 Demo 的 P0 功能范围，新增需求进入变更清单而不是直接插入当前阶段。

如果暂时没有测试环境，但具备真实事件样例，阶段 0、阶段 1 和大部分阶段 2 仍可启动；真实后端联调验收会保持未完成。
