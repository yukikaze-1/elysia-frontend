## 1. 体验目标

Cyrene 的主体验应接近成熟桌面聊天软件：信息层级明确、消息易读、输入顺手、状态可感知。Live2D 和工具执行应增强角色感与能力感，但不能抢占聊天主流程。

核心原则：

- 用户在任何时刻都知道当前会话、连接状态和 AI 状态；
- 工具执行过程可见，高风险行为不会隐藏发生；
- 生成、工具、上传和 Live2D 状态彼此独立；
- 错误尽量在相关对象附近展示；
- 允许键盘完成高频聊天操作；
- 窗口变窄或 Live2D 关闭时仍能完成全部聊天操作。

## 3. 主窗口布局

### 3.1 默认布局

```text
┌──────┬────────────┬────────────────────────┬──────────────┐
│ 导航 │ 会话列表   │ 当前聊天               │ Live2D      │
│      │ 搜索/新建  │ 标题与连接状态         │ 角色区域    │
│ 聊天 │            │                        │ 状态说明    │
│ 任务 │ 会话 A     │ 消息列表               │ 快捷动作    │
│ 设置 │ 会话 B     │                        │              │
│      │ 会话 C     │ 输入框与附件           │              │
└──────┴────────────┴────────────────────────┴──────────────┘
```

推荐尺寸：

| 区域 | 默认宽度 | 行为 |
|---|---:|---|
| 导航栏 | 60 px | 固定 |
| 会话列表 | 260 px | 可折叠 |
| 聊天区 | 自适应 | 最小 500 px |
| Live2D | 340 px | 可折叠、可调整 |

主窗口建议最小尺寸为 1100 × 700。该结构统一称为“四区布局”或“导航 + 三个内容栏”。Live2D 打开后必须作为聊天区右侧新增的布局列参与排版，聊天区随之收窄，禁止以覆盖层盖住消息、滚动条或输入区。窗口变窄时先保护聊天区最小可用宽度：可以折叠会话列表；若仍无法同时容纳聊天与角色栏，则自动关闭 Live2D，并保留显式重新打开入口。具体断点在实机布局测试后固化，不用原型单一宽度作为产品承诺。

> **已定案（2026-08-14，阶段 3 G1）：** 断点采纳 1200 / 736 / 520 / 320 四档；会话栏 260 可折叠、Live2D 右栏 **默认显示**、340 可调（[300,420]）；最小窗口 **1100×700**；窄窗自动折叠会话栏/关闭 Live2D 保护聊天区（effective-layout 纯函数计算，`renderer/src/layout/`）；布局记忆走 Renderer localStorage（键 `cyrene.layout.v1`，见 docs/06 §8.5）。

> **范围修正（2026-09-12，全量评审 M-23 处置）：** 上条"四档断点"中的 **736 / 520 / 320 三档在实现层面从未可达，其代码已删除**，本文件不再把它们当作已交付能力。实测依据：窗口硬最小宽度为 1100（`main-window.ts` 的 `minWidth` = `layout/constants.ts` 的 `MIN_WINDOW_WIDTH`），故 renderer 视口恒 ≥ 约 1084px；而仓库里 9 处 `@media (max-width: 560/680/720/760px)` 因此**永不匹配**，`BREAKPOINTS` 常量也只被自身定义与断言其数值的测试引用——即当时"断点已落地"的表述里，**结构性行为（按宽度折叠/关闭，effective-layout 纯函数）确实成立，而按断点做的 CSS 视觉微调从未生效**。
>
> 现口径：① **固定布局 + 硬最小宽度 1100**，窄窗保护由 effective-layout 纯函数按宽度推导（这一部分不变、仍在生效）；② **窄窗口（<1100）下的响应式分层未实现**，属**已知产品缺口**而非已完成能力——若将来要做，需要先决定是否放宽窗口最小尺寸，再让各视图真正在 320–760px 可用；③ 已加**回归门禁**（`tests/unit/layout-breakpoints.spec.ts`）：任何 `max-width < MIN_WINDOW_WIDTH` 的媒体查询即红，防止"看起来有响应式分层"的死代码再次混入。历史决策与测试记录保留不改（见 `docs/superpowers/specs/2026-08-14-phase3-layout-responsive-design.md`、`docs/review/2026-08-14-阶段3-决策记录.md`）。

## 4. 全局状态展示

> **UII-QQ 设置页批次注记（2026-08-30）：** 连接状态入口已移至**左侧导航栏底部**（全局运行状态，不属于单个会话）——插头图标 + 右下角状态点，点击展开连接浮层（状态摘要 + 展开的连接设置）；聊天头部不再承载连接状态。下表为浮层内的状态表达：

| 状态 | 展示 | 用户操作 |
|---|---|---|
| 正在连接 | 黄色状态点 +“连接中…” | 等待 |
| 已连接 | 绿色状态点 +“已连接” | 无需操作；可「断开」 |
| 正在重连 | 黄色状态点 +“重连中…” | 可手动重试 |
| 未连接 | 灰色状态点 +“未连接” | 打开连接设置 |
| 连接失败 | 红色状态点 +“连接失败” | 展开错误详情、重新配置凭据 |
| 协议不兼容 | 红色“版本不兼容” | 查看详情 |

通知分级：

- 与某条消息有关的错误显示在消息旁；
- 与某个工具有关的错误显示在工具卡片内；
- 全局连接错误显示在连接入口浮层内，断线/重连横幅显示在输入区上方；
- 只有需要立即处理的错误使用对话框；
- 普通成功操作不频繁弹 Toast。

## 7. 消息列表

### 7.1 消息表现

| 类型 | 表现 |
|---|---|
| 用户消息 | 右侧气泡或明确的用户样式 |
| AI 消息 | 左侧内容块，支持 Markdown |
| 系统消息 | 居中、低强调 |
| 工具调用 | 嵌入 AI 流程的结构化卡片 |
| 错误消息 | 附着于失败对象，不伪装成 AI 文本 |

用户消息应保留换行和附件；AI 消息优先可读性，不把长 Markdown 强行装入窄气泡。

### 7.2 一次 AI 回复的连续分段

后端流式处理器把一句完整回复切成多句连续发送时，界面采用“回复组”而不是“多条消息”：

- 同一 `responseId` 只显示一次头像、名称、主时间和消息操作区；
- 每个句子分段可保持独立的柔和气泡，以保留角色说话节奏；
- 分段之间的间距小于不同消息之间的间距，连续视觉边界清晰；
- 句子分段完成时不出现新的头像、未读数或通知；
- 父级回复完成后统一显示输入、输出、总 Token、实际模型、心情和完成状态；

> **落地更正（2026-09-15，对照代码逐字复核）——上一行只有「总 Token／实际模型／心情」落地：** 助手气泡的低权重元数据行渲染 `message.model`、`message.usage.total`（`CyMessageBubble.vue:248-251`）与 `message.emotion`（`:247`）；**「输入/输出 Token」从未显示**（`usage.input`/`usage.output` 在 renderer 组件里 0 命中），**「会话级 Token」也没有展示面**——后端 `conversationUsage` 只走到 `shared/domain/stream-accumulator.ts:181` 的 accumulator state，renderer 全域 0 命中。该行按**部分实现**读。

- 搜索、复制、重新生成、TTS 和反馈默认作用于整条回复，必要时可定位具体分段。

### 7.3 Inner Voice 与 Public Reply

后端的一条 Assistant 消息可以同时包含 `Inner Voice` 和 `Public Reply`。两者共享同一消息头像、时间、状态和消息 ID，但必须分区展示：

- Inner Voice 使用低强调底色、明确标签和可折叠区域；
- Public Reply 位于主要阅读区，视觉权重更高；
- 两种通道可以包含多个有序分段并分别流式更新，不生成多条独立 Assistant 消息；
- ~~回复组按全局 `segmentIndex` 形成一条时间线；相邻 Inner Voice 分段在它们出现的位置合并成低强调可折叠块，相邻 Public Reply 分段显示为主回复气泡。若后端再次切回 Inner Voice，则在该位置创建新的 Inner Voice 块，不能把所有 Inner Voice 强行移到顶部而破坏顺序；~~ **本行已被 U-3 裁决取代（2026-09-15）——见下方注记。**
- Inner Voice 缺失时不显示空区域；
- 默认复制只复制 Public Reply；“复制完整回复”按全局时间线保留 Inner Voice/Public Reply 标签和顺序；
- TTS 默认只朗读 Public Reply；
- 不把调试信息或模型隐藏推理当作 Inner Voice 展示。

> **U-3 裁决（2026-09-15，产品决定：改规格、接受置顶行为）**：上一行「不能把所有 Inner Voice 强行移到顶部而破坏顺序」
> 及其下「待裁决」注记作废。**现行规格改为**：一条 Assistant 消息内 **Inner Voice 分段整体收集并置顶**为
> 一个低强调可折叠块，**Public Reply 分段随后按 `segmentIndex` 顺序主区展示**；两者不做跨通道交错。
> 实施形态即既有代码（`CyMessageBubble.vue` 按 `channel` 分两个 computed，模板把全部 `inner_voice`
> 放进同一个置顶 `<details>`，再渲染 `public_reply`）——**代码不改**。
> 同时作废的还有验收清单里「并保持全局顺序」一句（见本文 §… 验收清单对应行）。
> **代价如实记录**：通道间的时间交错信息在展示层不可见（默认折叠更弱化位置感）；若日后要求交错，
> 属**规格变更**而非缺陷修复。裁决依据与取证见 [维护文档全面 review 报告](review/2026-09-14-维护文档全面review-报告.md) §16.4 的 U-3。

### 7.4 Markdown 与多媒体

支持标题、列表、引用、表格、链接、行内代码和代码块。

- 代码块显示语言、复制按钮和横向滚动；
- 表格在窄窗口内横向滚动；
- 外部链接带外部打开提示；
- 图片限制最大展示尺寸，可点开预览；
- 视频显示封面、时长、播放状态和全屏入口；
- 音频显示播放/暂停、波形或进度、时长和下载状态；
- 播放前按实际 MIME/编解码器能力探测；不支持的格式显示文件信息、下载/受控外部打开入口，不伪装成可播放；
- 图片、视频、音频加载失败时保留类型、文件名、重试和下载入口；
- HTML 和脚本不执行；
- 流式期间降低重复解析频率。

### 7.5 消息操作

用户消息：复制、重新发送；P1 增加编辑并重新生成。

AI 消息：复制 Public Reply、复制完整回复组、折叠 Inner Voice、重新生成、停止生成、播放 Public Reply 音频、查看消息 Token/模型/心情；P1 增加反馈和分支。

操作按钮默认弱化，鼠标悬停或键盘聚焦时显示。触屏兼容不是 Demo 阻塞项。

### 7.6 历史懒加载与滚动规则

- 用户位于底部附近时，流式内容自动跟随；
- 用户主动上滚后暂停自动滚动；
  - **"主动上滚"的落地判据（2026-09-13，按实测定的数）**：自上次确认贴底以来**累计**上移 ≥64px 才算；
    单次几十像素的下移不放弃跟随——实测里正是"浏览器在我们贴底写入之后自己回退 31px"被读成用户上翻，
    导致跟随意图被永久清掉（复现、读数与判据见 [doc 16](16-Cyrene-前端实施任务清单与进度跟踪.md) §3.1 的 ④ 收口）。
    累计而非单次，是因为触控板小步上滑每次只有几像素到几十像素；
  - "回到底部"按钮仍是显式恢复入口（`atBottom=false` 时可见）。
- 新内容到达时显示“回到底部”；
- 加载更早消息时保持当前可视锚点；
- 切换会话恢复该会话最近滚动位置；
- 大量消息使用虚拟滚动时，代码块和图片高度变化不能造成明显跳动。

### 7.7 聊天历史查看器

输入框上方工具栏右侧的“聊天记录”与“图片/视频”入口打开同一个 QQ 式历史查看器，不再维护互相割裂的消息搜索面板和资源窗口：

- 顶部支持关键词搜索，以及按用户本地自然日选择日期；跨时区查询按当前 IANA 时区换算，午夜附近消息不得归错日期；
- 分类为全部、图片/视频、表情、文件、音频、链接；“图片/视频”快捷入口直接定位图片/视频分类；
- 全部列表按日期分组，并显示时间、发送者、命中片段和内容类型；
- 图片/视频分类承载会话媒体（图片、视频），表情分类集中展示已发送表情包；
- 点击结果后关闭查看器，懒加载目标附近历史并高亮来源消息或回复组分段；
- 命中 Inner Voice 时先定位回复组，再按用户当前折叠设置决定是否自动展开；
- 使用不透明游标懒加载，打开查看器不阻塞聊天流；

## 8. 输入区

### 8.1 输入规则

- `Enter` 发送；
- `Shift + Enter` 换行；
- 中文输入法组合期间不得误发送；
- 空白消息不可发送；
- 发送失败保留原文；
- 切换会话时分别保存草稿；
- 生成期间允许编辑下一条内容。
- 支持从系统文件管理器拖拽一个或多个文件到聊天区域。

### 8.2 按钮

- 添加文件；
- 录制语音输入或进入实时语音会话；
- 表情/表情包；
- 按住说话转文字；
- 主动截图；
- 发送；
- 生成时显示停止按钮；
- 上传中显示附件进度和取消。

### 8.3 附件条目

显示名称、类型、大小、上传状态、移除按钮。文件校验失败时直接在条目中说明原因。

> **阶段 3 修订（2026-09-10，附件渲染失败的占位语义）：** 媒体元素 `error` 时经 `attachments:check` 分类，但**「附件在服务端可用」与「本机能否渲染」是两个独立信号**——字节完好而浏览器解不开（截断图片、容器/编解码不受支持）时分类会返回 `ok`，此时若沿用 `ok` 就会保留一个静默损坏的元素，既无解释也无重试入口。因此渲染失败单独表达为**可重试占位**，文案「无法显示该附件」（不谎报「不存在/已过期」，避免把用户引向重新上传），重试仍走 `attachmentsCheck` 并在仍 `ok` 时换 nonce 重新请求媒体。同时明确：attachment 分类为 expired/not_found/revoked/error 时给出的占位文案与「重试/刷新」入口不变（见 §8.3 上表与阶段 3 附件设计 §4.7）。决策与真机证据见[修复决策记录](review/2026-09-10-三项产品缺陷与集成孤儿进程修复-决策记录.md) §3.2。

拖拽进入聊天区域时显示覆盖式虚线投放区和支持类型说明；离开后立即恢复。松开后只创建待发送附件条目，用户仍可移除、补充文字或取消，客户端不得自动上传或发送。目录、超量文件和不支持类型要逐项解释；点击添加、拖拽和粘贴使用同一附件状态机。

### 8.4 语音输入

普通录音输入和实时语音会话属于“直接语音输入”，与输入法转写分离：

- 普通模式录音结束后生成待发送的音频输入，用户确认后发送；
- 实时模式由用户明确开始/停止，并按后端对齐后的 VAD/断句规则提交语音轮次；
- STT 的 partial/final 可以显示为字幕或识别状态，但不得写入可编辑文字草稿；
- 麦克风按钮显示空闲、正在监听、处理中、待发送/会话中和失败；
- 第一次使用前请求系统麦克风权限；
- 字幕与用户文字输入视觉区分，并明确“字幕不会加入输入框”；
- 普通录音停止只形成待发送语音输入，不自动发送；
- 实时会话不可用时只能提示用户改用普通录音，不能静默改变数据上传位置；
- STT 字幕失败不丢弃已经录制或正在处理的语音输入。

> **阶段 4 批次 B 落地（2026-08-16，Mock 驱动，标「已开发、未联调」）：** 输入区语音入口已实现——**🎤 普通录音**（click 开始/停止，录音中按钮高亮 + 时长）、**🔊 实时会话**（进入后输入区替换为 `CyRealtimeBar` 实时状态条：聆听状态 + 字幕 + 轮次数 + 停止；实时进行中聊天发送按钮禁用）、**⌨️ 输入法转写**（pointerdown 开始 / pointerup 提交 / 上滑取消，`CyDictationHint` 字幕浮层）；入口**禁用态**：语音输入总开关 `enabled` 关 → 🎤/⌨️ 禁用，`realtimeEnabled` 关 → 🔊 禁用（`voiceStore` 统一守卫）。录音停止后 `CyVoicePending` 待发送条（转写字幕或「未识别，请重试」+ 试听/重录/删除/确认发送，无字幕时确认发送禁用）；**后端 STT 首次操作前一次性同意对话框**（D-P16，「不再提示」持久化 `voice.consentBackendStt`）；TTS 自动朗读经 `CyTtsPlayer`（隐藏 `<audio>`，宿主 CyChatView，`autoReadReply` 播放门 D-P1）；**会话切换守卫**（语音会话活跃 `mode≠idle` 时禁止切换/新建会话，提示先结束，D-P5）。

### 8.5 表情与表情包

- 输入区提供常用 Emoji 和表情包两级面板，最近使用项优先；
- Emoji 作为可编辑文字插入光标位置；表情包作为结构化 `sticker` 附件进入待发送区；
- 表情包消息在聊天记录查看器的“表情”分类集中展示，并能跳回来源消息；
- 表情资源保存稳定 ID、版本和缩略图引用，不把本地绝对路径写入消息；
- 插入表情或选择表情包均不自动发送。

### 8.6 按住说话转文字（输入法转写）

该功能与普通/实时 STT 的产品语义分离：用户按住专用按钮录音，松开后将最终文字写入当前输入框，允许继续编辑，不创建语音消息，也不自动发送。

- 按住、录音、松开转写、取消和失败状态必须清晰；
- 临时音频仅用于本次转写，完成、取消或失败后按策略删除；
- 设置中有独立的输入法转写开关和专用 STT Profile 选择；
- STT Profile 的执行位置可为 Backend、本机或 Local Worker；选择 Backend 时明确提示音频会离开设备；
- 底层是否复用普通 STT 模型和接口仍待前后端讨论，前端保持独立功能开关和 Profile ID，避免产品行为耦合。

> **阶段 4 批次 B 落地（2026-08-16）：** 转写「按住→松开→final 写草稿」已实现（`CyDictationHint` 浮层字幕；`dictation.final` 按 `dictationInsertMode` 追加草稿末尾或替换当前选区，**不创建语音消息、不自动发送**；上滑取消 → `dictation.cancelled` 清态）；转写可独立选择 STT Profile（语音设置子页下拉，D-P14/D-P20）。

## 11. Live2D 区域

包含：

- 角色画布；
- 加载或降级占位；
- 当前公开状态，如“正在思考”；

> **交互口径补充（2026-09-12，全量评审 M-21/M-22 处置）——以下两条此前**未被本文件规定过**，实现里也不存在，现补为规范：**
>
> **① 「按住说话」的键盘等价语义。** 原实现只绑指针事件（`pointerdown/move/up/cancel`）；它是原生 `<button>`，可 Tab、看起来可操作，但键盘唯一能产生的 `click` 没有处理器 ⇒ WCAG 2.1.1 失败且**无任何替代路径**。现规定：
> - 聚焦后按 `Enter` 或空格 = **按住**（keydown 起采集、keyup 提交），与指针路径语义一致；
> - 系统按键自动重复（`e.repeat`）**不得**重入采集；
> - 该键须抑制默认激活行为（不产生合成 `click`），因此不存在"keyup 已提交、click 又重开"的重复进入；
> - 按住期间若焦点离开（Tab 走开），必须**收尾提交**，不得留下无 UI 可解释的持续采集；
> - 采集期间以 `aria-pressed` 暴露"按住中"。
>
> **② 后端 STT 一次性同意框的可关闭性与焦点。** 原实现 `role="dialog" aria-modal="true"` + 全屏覆盖，却**零焦点管理**（无初始焦点、无 Tab 陷阱、无回焦）。现规定：
> - 打开时**把焦点移入对话框，初始落在「取消」**（安全默认：用户若直接按 Enter，回答的是"拒绝本次"，而不是在未读提示时就把同意持久化）；
> - Tab/Shift+Tab 在框内循环；关闭后**回焦触发元素**（触发元素已卸载则不强行聚焦）；
> - `Escape` **等价于「取消」=「拒绝」**：它只清除本次挂起、**不写入**同意状态、不执行挂起动作，下次语音操作仍会重新弹窗 —— 故它不构成"绕过同意"（没有同意就没有上传）。产品语义上"拒绝"是允许的答复之一，被禁止的是**未答复就继续**；
> - 例外：当用户**已同意**且挂起动作在途时（`confirmDispatching`），`Escape` 不关闭 —— 此时"取消"不再等价于拒绝，关掉只会留下无 UI 可解释的中间态。
