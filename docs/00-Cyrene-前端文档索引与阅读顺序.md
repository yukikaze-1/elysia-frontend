## 1. 文档集定位

这套文档用于指导 Cyrene Electron Demo 前端设计、开发、联调、测试和发布。

v0.2 已补充：LLM/STT/TTS 的接入、测试、切换和自定义 Profile；普通录音输入、实时语音会话与按住说话转文字；完整安全策略、权限审批与范围授权、Live2D 切换、外观调节、前端日志和开发者模式；并明确“一次 AI 回复、多个按句流式分段”的回复组模型，补充 Inner Voice/Public Reply 全局分段顺序、消息/会话 Token、实际模型、心情、多媒体消息、拖拽附件、历史懒加载，以及整合消息搜索、媒体、表情、文件和链接的 QQ 式聊天历史查看器（后端六分类：图片/视频、表情、文件、音频、链接）。角色栏打开时固定在聊天区右侧扩展，不覆盖聊天内容。

2026-08-04 首轮交叉 Review 已统一三项关键口径：输入法转写复用兼容 STT Profile，而不是第四种模型服务；直接语音字幕不写入文字草稿；工具统一使用带命名空间的 ID 和 `callId`，`desktop.command.run` 为需单独确认的可选能力。

已有后端经过多次迭代，因此本文档集遵循以下边界：

- 不重新设计后端内部架构；
- 不要求后端采用文档中的推荐 URL 或字段名；
- 通过 `BackendAdapter` 接入现有后端；
- 前端通信文档定义稳定的前端领域语义；
- 与后端尚未核对的项目明确标注为“待对齐”。

## 4. 不同角色的阅读路线

### 产品 Review

```text
13 Review 记录 → 主需求 → 工具补充需求 → 03 UI → 05 Live2D → 08 验收
```

重点确认界面布局、权限文案、Demo 范围和验收脚本。

### 前端负责人

```text
12 启动清单 → 01 架构 → 02 通信 → 06 状态 → 07 安全 → 10 实施
```

重点确认进程边界、Adapter、Store、IPC 和实施依赖。

### UI 开发

```text
03 UI → 02 数据事件 → 04 工具权限 → 05 Live2D
```

重点确认组件状态、消息类型、工具卡片和响应式布局。

### Electron/Main 开发

```text
01 架构 → 04 工具权限 → 07 安全 → 06 存储 → 09 构建
```

重点确认 IPC、文件/截图、凭据、审计和平台差异。

### 测试

```text
08 测试 → 02 通信 → 04 工具权限 → 07 安全 → 09 发布
```

重点确认异常、重放、跨平台和发布门槛。

## 5. 文档之间的优先级

发生冲突时按照以下顺序处理：

1. 用户最新确认的产品决策；
2. 主需求的产品范围和已确认的工具补充语义；
3. 安全与权限不可绕过约束；
4. 已与后端实际联调确认的通信契约；
5. 其他前端详细设计；
6. 实施路线中的建议顺序。

不能为了与 UI 草图一致而降低安全约束，也不能为了保留文档中的推荐字段而强迫现有后端无意义改名。

## 6. 当前需要优先 Review 的决策

### 产品和 UI

- Live2D 右侧扩展栏的默认宽度、最小聊天区宽度和极窄窗口自动关闭阈值；
- Live2D 默认显示还是默认折叠；
- 工具调用过程是否默认展开；
- 文件写入 Diff 的详细程度；
- Demo 是否包含 TTS 和语音播放。

### 后端对齐

- 流式协议：WebSocket、SSE 或混合；
- 认证方式；
- 会话和消息 ID；
- 工具调用/结果/取消结构；
- Inner Voice 与 Public Reply 的字段和流式顺序；
- `responseId/segmentId/segmentIndex` 与父回复完成事件；
- 回复/会话 Token、实际模型和心情字段；
- 历史游标、会话搜索，以及统一聊天历史的关键词/日期/分类查询和来源跳转接口；
- LLM、STT、TTS Profile 管理、测试、自定义 CRUD 和凭据所有权；
- 输入法转写专用 STT Profile 的字段，以及 Backend、本机、Local Worker 中首版开放哪些执行位置；
- 普通录音输入、实时语音字幕、VAD、断句和语音轮次事件；
- Backend 与 Desktop Runtime 的标识；
- 附件上传方式；
- 心跳、续传和错误结构。

### 平台与发布

- Windows 是否为首个主验收平台；
- Ubuntu 目标版本和桌面环境；
- Wayland 是否为 Demo 强制项；
- 安装包格式和发布渠道；
- Live2D 模型与 SDK 的合法分发范围。
- 沙盒、路径/域名黑名单和历史授权的默认规则；
- 受控命令模板是否进入 Demo；
- 开发者模式在生产构建中的开放方式。

## 7. 文档维护规则

- 每份文档独立记录版本和状态；
- 后端真实协议变化先更新 02 的对齐表和 Adapter，不直接改 UI；
- 权限策略变化同步更新 04、07 和 08；
- 新增用户可见功能同步更新主需求、03 和 08；
- Live2D 资源或 SDK 变化同步更新 05、07 和 09；
- 发布目标变化同步更新 08、09 和 10；
- 被确认的补充需求最终合并进主需求，避免长期存在多个互相覆盖的事实来源。
