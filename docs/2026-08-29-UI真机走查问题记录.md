## 问题 1：消息区滚动条滚动时抖动

**现象：** 滚轮或拖拽滚动条上下滚动时，聊天区右侧滚动条 thumb 抖动/跳动。

**定位：**
- 滚动容器：`CyMessageList.vue:272` `.cy-messages { overflow-y: auto }`（无 `scrollbar-gutter`，Windows 经典占位滚动条）。
- 高度修正机制：`CyMessageList.vue:103-127` `onRowResized`——滚动中新行进入窗口，ResizeObserver 实测写 `heights` → `buildPrefix` 前缀和变化 → `paddingTop/paddingBottom`（L245/257）变化 → 容器 `scrollHeight` 变化 → thumb 位置与长度跳变。
- 主动位移：`CyMessageList.vue:116-126` 锚点上方行高变化时 `container.scrollTop += delta`；向上加载 `restoreLoadAnchor`（L79-92）回写 scrollTop。

**机制分析（按贡献度）：**
1. **估高→实测修正**（主因）：滚动过程中实测高替换估高，`scrollHeight` 持续变化，thumb 随之跳；拖拽时 thumb 在光标下移动，感受为「抖动」。这是估高式虚拟列表的固有代价，当前估高函数误差越大越明显。
2. **锚点补偿/加载恢复**（次因）：防内容跳动的设计副作用是滚动条瞬时位移。
3. 与[精修整改清单](2026-08-29-UI精修整改清单.md) §3 的「闪烁」（滚动条出现/消失致横向跳动）**不同源**，是两个独立问题：§3 用 `scrollbar-gutter: stable` 解决；本条解决不了，需单独处理。

**置信度：** 高（机制与症状吻合；无需复现实验即可确认路径）。

**修复方向（候选，未拍板）：** 滚动中延迟/批处理高度提交（scrollend 或 rAF 合并）、改进 `estimateHeight` 降低修正量、拖拽期间冻结补偿。注意红线 §4：改动必须复跑 perf-gate ②/③；禁止绕过虚拟化。

**验证口径：** 长会话（100+ 条）匀速滚轮滚动目测 thumb 稳定；按住 thumb 拖至中部持续不动，目测无自跳。

## 问题 2：消息底部「Cyrene · completed」下出现空的小药丸

**现象：** 列表底部 assistant 消息头部正常，正文位置只有一个空的小圆角药丸（强调色底），无任何文字。

**定位：**
- `CyMessageBubble.vue:105`：`<CyMarkdown :source="needsDeferredRender(seg) ? '' : segmentText(seg)" />`——7D 视图感知暂停：行在 strict 可见窗口外（`rowVisible=false`，CyMessageList.vue:51-53）时，completed segment 以**空 source** 延迟渲染。
- `CyMarkdown.vue:52`：恒渲染 `<div class="cy-markdown" v-html>`——空 source 也渲染外壳。
- `CyMessageBubble.vue:234-242`：`.cy-segment` 空内容仍画出完整药丸底（accent 背景 + padding + fit-content）。

**机制：** 窗口边缘行因估高偏差 + strict 窗口无 overscan，被判为「不可见」→ 延迟渲染 → 用户实际看得见的位置留下空药丸；空内容又使实测高偏小，行更难进入 strict 窗口，状态自持，直到滚动/resize 触发重算。这是 7D 真机已修问题族（`e774195` borderBox 欠估「半可见空行」）的近亲——上次修的是窗口判定，本次暴露的是**延迟态的渲染形态**。

**判别方法（修复前先复现确认）：** 轻微滚动或 resize 窗口——若药丸瞬间填充正文，即为延迟渲染路径（主假设，置信度高）；若持续为空，再查 mock 数据是否返回空白 segment（备用假设）。

**修复方向（候选）：** 延迟态改渲染骨架占位或完全不渲染该 segment（不留空样式药丸）；或对 strict 窗口边界行强制实时渲染。红线 §4：改动需复核 perf-gate ③（视图感知暂停断言）。

**验证口径：** 长会话滚动全程视口边缘不出现空药丸；perf-gate ②/③ 全绿。

## 问题 6：聊天头部信息架构混乱（三类异质内容混一行 + 冗余按钮）

**现象：** 头部一行内挤着：状态点 + 会话名（截断「hi~爱…」）+ 状态文字（折行「未连/接」）+ [聊天记录 / 资源 / 新建 / 角色] 四个按钮 + MOCK 演示模式 chip + 连接按钮。开发者质疑「这些东西放在这里合适吗」。

**定位：** `CyChatView.vue:68-89`——`cy-chat-header` = `cy-chat-heading`（`cy-online-dot` + `h2 convTitle` + `cy-status-text`）+ `cy-header-actions`（聊天记录 L78 / 资源 L79 / 新建 L80 / 角色 L82-87 / `CyConnectionPanel` L88）。

**结构成因：** 阶段 2 放连接面板、阶段 3 加聊天记录/资源/新建、阶段 5 加角色——每批次往头部塞一个入口，从未做信息架构整合，头部成为杂物抽屉。

**逐项判断：**

| 元素 | 性质 | 判断 |
|---|---|---|
| 会话名 | 会话上下文 | 与左侧会话列表高亮项**重复**；截断后（「hi~爱…」）信息价值为负 |
| 状态文字「未连接」 | 全局状态 | 语义错位（非会话属性）且折行难读；最该一眼可见的信息反而最难读 |
| 聊天记录 / 资源 | 内容入口 | 原型头部固有（原型 L2746-2752），**保留合理** |
| 新建 | 冗余 | 原型里新建在会话列表头（+ 按钮，原型 L2697）；实现中列表 + 与头部「新建」两入口并存 |
| 角色 | 布局开关 | 与内容入口异类但可容忍；可收进溢出菜单 |
| MOCK chip + 连接按钮 | dev/联调控件 | **最刺眼**：联调产物常驻产品 UI 最显眼位置，Mock 标识与产品按钮同视觉权重，首屏关键动作「连接」缩在角落 |

**收敛方向（候选，需拍板）：** 头部只留 状态点 + 会话名 + [聊天记录 / 资源 / ⋯溢出菜单（角色）]；删「新建」；状态用颜色点承载、文字不折行；连接引导改为「未连接时才出现的显眼引导」，Mock chip 降为小角标。注意红线：状态不能只靠颜色区分（红线 §7 需文字/chip 补充——可用 tooltip 或侧栏详情承担）；`CyConnectionPanel` 交互语义不回退（总原则 3），Endpoint/Token 设置入口仍需可达。

**验证口径：** 头部在四档断点下无折行无截断；连接/设置 Token 路径仍可达且未连接时有引导；单测选择器同步更新（红线 §9）。

## 问题 7：设置页「角色与外观」内容区 hover 时文字轻微上移（已定案：字形级重渲染）

**现象：** 设置中心 → 角色与外观子页，鼠标移入「互动/性能」分组区域后，里面的文字有时向上移动一点；鼠标移出后落回原位。间歇性出现。

**已排除（静态排查证据）：**
- 子页与设置壳层**无改几何的 hover 样式**：`CyLive2DPane.vue` 仅模型行/按钮 hover 改背景色（L257/273），`CySettingsView.vue` 仅导航项背景（L178）——无 border/padding/transform/line-height 类 hover 规则。
- 无 JS hover 路径：两组件无 `mouseenter/mouseover` 处理器。
- 无全局样式泄漏：全部组件 style 均为 scoped，无未加 scoped 的 style 块；无全局 checkbox/label 规则。
- 设置内容区 `overflow-y: auto`（CySettingsView.vue:184）无 `overflow-anchor` 特殊设置。

**剩余假设（按可能性排序，2026-08-29 控制台取证后更新）：**
1. **媒体重试循环驱动的 DOM 抖动**（升级为主嫌疑）：DevTools 控制台出现**连续多条** `cyrene://renderer/…/70a9b8fff06bd?t=0.1` **500（Internal Server Error）**——`?t=` 经定位是 `utils/media-url.ts:10` 的占位重试缓存破坏 nonce；nonce 恒为 `0.1` 说明重试循环未更新 nonce（或同一组件以同一 nonce 反复重挂载）。每轮重试可能切换占位/媒体 DOM 状态造成内容高度振荡——「有时上移、移出落回」可能实为重试节拍与 hover 的巧合相关。
2. Chromium 合成层提升/降级的亚像素重渲染：hover 触发重绘使文本在合成层边界间移动，亚像素灰度切换造成 ~1px 位移——若判别确认位移仅 1px 级且与 500 时间点无关，回到本假设。
3. 某个 hover 瞬态插入的元素（tooltip/提示条）推挤上方内容——静态排查未见。

**新增旁证：** 控制台同时出现 3 条 `ResizeObserver loop completed with undelivered notifications`（main.ts:28）——存在 resize 反馈循环，与问题 1 滚动条抖动机制同族（候选源：消息列表高度补偿 / 历史查看器 / Live2D 画布自缓冲）。

**判别实验结果（2026-08-29 第二轮）：**
- 勾选 Layout Shift Regions 复现：**文字仍移动但无蓝色高亮** → **排除布局位移**（非 DOM 插入/推挤——DevTools 未记录任何 layout change）。
- 复现期间**无新 500** → **排除问题 8 重试循环驱动**（500 与 hover 无时间相关性）。
- 结论收敛：位移是**绘制层面**（合成层/亚像素重渲染类）——这类移动不改变布局树，故无蓝框。

**下一步判别（一个问题定案）：** 复现时观察**动的是什么**——① 只有文字字形动、卡片边框不动 → 字形级重渲染（层/亚像素假设成立，修复方向：稳定内容合成层）；② 整张卡片连边框一起动 → 容器级 transform/滚动调整（换方向排查：全局 mousemove 监听（Live2D 鼠标跟随）→ reactive 级联嫌疑）。

**判别结果（2026-08-29 第三轮，开发者观察）：只有字形动、边框不动 → ① 成立。定案：hover 触发重绘时，字形在合成层边界/亚像素相位间重光栅化，产生 ~1px 垂直位移；无布局变化（与无蓝框一致）。Windows 分数缩放（125%/150% DPI）会放大此类相位跳变。**

**修复方向（定案）：** 为设置内容滚动容器做**合成层稳定**——内容包装层加 `transform: translateZ(0)`（或 `will-change: transform`），使文本恒定在同一光栅化路径，消除 hover 重绘引起的相位翻转；不加任何 layout/paint 类动画。红线 §10 合规（transform/opacity only）。附带说明：此为 Chromium on Windows 的已知渲染伪影族，修复属于缓解而非根除，真机验证以「hover 往复肉眼不可见位移」为验收口径。
