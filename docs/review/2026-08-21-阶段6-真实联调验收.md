## 3. 本轮发现并修复的问题

1. desktop 工具版本与后端注册版本不一致：统一为 `1.0.0`，真实后端状态查询已确认。
2. 后端 desktop placeholder 与本地 awaiting/running 更新存在竞态：调整 store upsert 顺序和副作用门控，保留截图捕获状态。
3. dev 页面访问 `cyrene://` 受跨源限制：联调期间曾临时把 scheme `corsEnabled` 打开以继续 dev 验证；2026-08-21 复核认定该开关违反阶段 5 D-4 安全结论（放开后非受信 origin 可读 `cyrene://` 资源），**已回退为 `false` 并补回断言**。剩余真机验证必须使用 preview/prod 同源启动（`pnpm build` + `electron .`），不再以 dev 跨源 fetch 为前提。
4. 截图源列表/预览区域会撑开卡片：改为卡片内部滚动布局。
5. 当前后端仍发送 `delta`、`message`、`token_usage` 兼容输出帧：补严格 schema/type、显式 no-op、真实 wire fixture 与 contract 白名单，消除 `RAW_FRAME_INVALID`。
6. Live2D 状态优先级实现与清单相反：`toolWaiting` 现在仅次于 disconnected/error，高于 thinking/speaking；终态后恢复当前业务态。
7. 后端工具截图 ContentPart 仅含受鉴权 `/uploads/desktop/{callId}.png` 且无 `attachment_id`，原映射会丢媒体。已增加固定路径/MIME 的安全元数据派生、Main 鉴权字节代理（ID/MIME/16 MiB/PNG 魔数校验）和归档卡渲染；Renderer 不接触后端 URL 或 Token。

## 3.1 本轮新发现、尚未修复

1. 后端 `DesktopToolBridge` 默认等待窗口为 **120 秒**（`core/desktop/bridge.py timeout=120.0`；真实 `desktop_calls.expires_at = created_at + 120s`）。此前记录的“60 秒归档 timeout、70 秒晚到成功”需与该 source call 对应的桥 call 的 created/expires 重新对齐——当前证据不支持 60 秒结论，先按 120 秒口径记录；若确认晚到成功不能替换已归档 timeout，作为独立后端语义项单开。
2. `CyLiveToolCards` 曾读取全局 live records，成功但未归档的终态卡片在切换会话后仍显示。2026-08-21 收口批已实现会话隔离（`conversationId` 从 Main `tool.request` 贯通到 `PublicToolEvent` → `toolStore`，实时区按活动会话过滤；未归属/活动会话未知时兼容显示），**待 Windows 真机复验**。
