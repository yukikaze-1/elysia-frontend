## 2. 证据缺口详述（真实核查结论）

### 2.1 第 11 项（自定义 Endpoint SSRF/DNS/重定向/Header 面）

- **核查**：grep 阶段 4/6 测试面——`tests/unit/` 无 endpoint 安全专项（connection-config.spec.ts 仅连接面板 URL 规范化 8 用例；real-backend-model-services.spec.ts 为 Profile 命令链路；model-handlers.spec.ts 为 IPC 接线/schema/apiKey 剥离）；`src/main/models/model-handlers.ts` 全为 thin proxy——`adapter.testModelProfile` 直转后端命令（`POST /api/providers/test`），**出站请求的网络面由后端执行**，前端无 SSRF/DNS/private-IP/重定向/Header 校验实现。
- **结论**：证据缺口成立（非前端漏测，是前端无实现面）。前端已有证据 = schema maxLength + 连接面板 URL 规范化 + 传输链路测试。该面与「连接面板 Endpoint」的 http/https/回环规则（连接配置正常做）不同——模型 Profile Endpoint 的深度校验在后端侧。
- **影响面**：doc 07 §7 的「自定义模型 Endpoint 视为不可信出站目标」清单对前端仅可执行「规范化协议/主机/端口 + Header 允许名单」部分（若未来前端直连模型，需另行实现）；当前按「后端职责」记录，需后端侧按 doc 07 §7 核对；Demo 范围（模型 Profile 测试在后端执行）不受影响。

### 2.2 第 18 项（发布包来源/完整性）

- **核查**：verify:artifact 现状 = 静态检查（产物存在/CSP/秘密扫描/version/Fuses 读回）+ `--smoke`（Playwright + CP + flip-back 副本）+ CI `artifact` job（clean + package + `--smoke` + `git rev-parse HEAD > app-sha.txt` 上传）；**无签名、无校验和清单、无 OnlyLoadAppFromAsar/EmbeddedAsarIntegrityValidation**（本批评估记录：启用需 asar:true 全家桶 + H-04 签名联动）。
- **结论**：**部分满足**——来源可追溯（commit SHA + 可重跑构建）已有；第三方鉴证完整性（签名/校验和）缺，归阶段 8（H-04 外部依赖未到位，spec §12 进入条件清单中）。
- **影响面**：阶段 8 打包批次（Windows 签名证书、Linux 包格式与发布渠道）为最终落地面；本批不阻塞，验收记录为「证据缺口 + 阶段 8 承接」。
