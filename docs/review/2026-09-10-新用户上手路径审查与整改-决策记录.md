# 新用户上手路径审查与整改（2026-09-10）

**记录日期：** 2026-09-10

**文档状态：** 生效中

**审查动机：** 反馈「前端启动命令对新用户不友好」。不做主观判断，实测「全新机器按文档照做」会撞到什么。

**审查口径：** 逐条**实跑**文档里的命令并记录真实输出，而不是读文档推测其正确性。

---

## 1. 结论

**启动命令本身并不复杂——`pnpm dev` 一条即可，实测干净启动。** 真实摩擦集中在三处，且都不是「命令太长」：

| # | 问题 | 性质 | 严重度 |
|---|---|---|---|
| A | 根目录缺 `start` / `live2d:install` 别名；`pnpm start` **直接报错** | 文档与工程不一致，照做即失败 | 高 |
| B | **Live2D 模型装配步骤从未被文档记录**，而缺模型时面板显示「模型不可用」 | 静默失败点：跑起来了但功能是坏的，新用户无从下手 | 高 |
| C | 工具链安装（fnm / pnpm / Node 版本）无脚本、错误恢复路径靠人 | 一次性成本，但失败时不知道下一步 | 中 |

其中 **B 是本次最重要的发现**：`apps/desktop/scripts/live2d-install.mjs` 与 `live2d:install` 脚本**早已存在且可用**，但 README、doc 16、doc 17 **三处入口都没有提到它**。新用户按文档走完全部步骤，启动成功，然后在角色面板看到「模型不可用」，没有任何线索指向那个已存在的工具。

## 2. 实测证据

### 2.1 `pnpm dev` 干净启动（不是问题）

```
dev server running for the electron renderer process at:
  ➜  Local:   http://localhost:5173/
electron main process built successfully
electron preload scripts built successfully
starting electron app...
```

窗口标题 `Cyrene` 正常出现。唯一 stderr 是一条无害的 bundler 提示（`INEFFECTIVE_DYNAMIC_IMPORT`，`safe-open.ts` 同时被静态与动态导入）。

### 2.2 `pnpm start` 从根目录直接失败（问题 A）

```
$ pnpm start
[ERR_PNPM_NO_SCRIPT_OR_SERVER] Missing script start or file server.js
exit: 1
```

根 `package.json` 有 `dev`/`build`/`test` 等别名，却唯独缺 `start`——而同级的 `live2d:install`、`ensure:electron`、`start` 也都缺。README 正文写的是带 `--filter` 的完整形式（可用），但新用户从「同源运行」小节里摘 `pnpm start` 是很自然的动作。

### 2.3 `pnpm install --frozen-lockfile` 幂等通过

```
Scope: all 2 workspace projects
Already up to date
Done in 359ms using pnpm v11.20.0
exit: 0
```

### 2.4 Live2D 模型确实不在仓库里（问题 B）

```
$ git ls-files apps/desktop/src/renderer/public/live2d
14 files —— 全部是 Cubism Core（live2dcubismcore.min.js）+ 13 个 shader

按扩展名统计 public/live2d：
  .frag  8 files   0.0 MB
  .vert  5 files   0.0 MB
  .js    1 files   0.2 MB
```

**零个模型文件。** 模型由 Main 侧 `Live2DModelRegistry` 从 **userData 的 `models/`** 读取（`src/main/persistence/user-data-dirs.ts` 的叶子之一），不是从仓库读。

### 2.5 文档与实际路径不一致

| 文档 | 写的路径 | 实际 |
|---|---|---|
| doc 05 §4 | `assets/live2d/<model-id>/` | userData `models/<id>/`（Windows `%APPDATA%\Cyrene\models`） |

且 doc 05 给的 `manifest.json` 示例没有说明它**必须由装配工具生成**（连同 `integrity.json`）——手工摆放的目录会被注册表跳过或标记 `available=false`。

### 2.6 `predev` 版本门禁已存在（做对的地方）

`apps/desktop/package.json` 已有 `predev`/`prebuild`/`pretest` 调 `check-node-version.mjs`，且报错信息直接给出修复命令：

```
Node 版本需满足 >=22.23.0 <23（当前 v24.x.x）。请用 fnm 切换：fnm install 22.23.0 && fnm default 22.23.0
```

这一环不需要改。

## 3. 整改内容

### 3.1 补齐根别名（问题 A）

`package.json` 新增：

```
start          → pnpm --filter @cyrene/desktop start
live2d:install → pnpm --filter @cyrene/desktop live2d:install
```

验证：`pnpm live2d:install --help` → exit 0 并打印用法；`pnpm start` 不再报 `NO_SCRIPT`（改为真正拉起 Electron，符合预期）。

### 3.2 Live2D 模型装配写入文档（问题 B）

- **README** 新增「启动后还需一步：Live2D 模型」小节：明确「仓库不分发模型」「看到『模型不可用』是预期而非故障」，并给出装配命令。
- **doc 17** 新增 §3.1「Live2D 模型装配（首次启动后必做）」：完整参数表、脚本行为、三平台安装路径表，并显式标注 doc 05 的路径是早期示意、以 §3.1 为准。
- **doc 05 §4** 加校正注：运行时读 userData `models/`，且目录须由装配工具生成。

授权口径按既有决策：**不随仓库分发，只装配来源与授权明确的模型**（`EXT-01`）。

### 3.3 Windows 一键脚本（问题 C）

新增 `scripts/setup-windows.ps1`：检查 Node/pnpm 版本 → 按需 `pnpm install --frozen-lockfile` → 可选 `-Run` 启动。

**刻意的设计限制**（写进脚本头部注释）：

- **不代装 fnm / Node / pnpm**——它们改系统 PATH 或全局包，静默代劳会让新用户在出问题时不知道机器被改过什么。脚本只把「装什么、装哪个版本」讲清楚。
- **不吞失败**：任何一步失败即非零退出，并打印下一步该做什么。
- **版本单一来源**：Node 版本读 `.nvmrc`，pnpm 版本读 `package.json` 的 `packageManager`，脚本内不硬编码；Node 判定直接调用仓库自带的 `check-node-version.mjs`，避免脚本与 `predev` 门禁漂移。

验证：实测 exit 0，输出四步进度与 Live2D 提示。

> **实现坑（记录以免重犯）**：脚本含中文，首次以 UTF-8 **无 BOM** 写入时 `powershell.exe`（5.1）按 ANSI 解码导致解析失败（`Unexpected token '}'`、`<` 被当作运算符）。补 UTF-8 BOM 后正常。**本仓任何含中文的 `.ps1` 必须带 BOM。**

### 3.4 README 快速开始重写

拆成「首次准备（每条各跑一次）」与「每次启动（`fnm use` + `pnpm dev`）」两段，补上首次安装会下载约 215MB Electron 二进制（避免误判为卡住），并新增「常见坑」三条（含 `pnpm start` 报错、fnm 是 per-shell）。

## 4. 一处措辞的保守化（重要）

整改中发现 README/doc 17 原有断言：

> 「Live2D 和媒体资源走 `cyrene://` 且安全策略禁止跨源，因此这类验证**必须**使用同源运行形态」

**按代码推断，该断言很可能不成立**：

- `src/main/config/dev-csp.ts` 的 dev CSP **显式放行 `cyrene:`**——`connect-src 'self' cyrene:`，且注释写明「阶段 5 批次 A（Task 1）：dev 下 Framework 经 `fetch(cyrene://…)` 取 shader 文本」；`img-src`/`media-src` 同样含 `cyrene:`。
- `cyrene://` 协议处理器在**未打包时同样注册**（`src/main/index.ts`），dev 只省略 `rendererRoot` 且注明「媒体分支不依赖它」。

但**我只有代码层面的证据，没有 dev 形态下 Live2D 实际渲染的运行时证据**（本地无模型，装模型需所有者提供）。因此**没有把文档改写成「dev 下 Live2D 可用」**，而是：

- 把该小节从「完整同源运行（Live2D / 媒体 / 真实联调）」改名为「打包产物运行（发布形态验证）」，说明它是验证**发布形态一致性**（自定义协议、产物 CSP、打包资源解析）的手段；
- 显式加注「待实测确认」，并写明：若 dev 下真的报资源加载失败，说明存在 `corsEnabled` 层面的限制，本节措辞需相应修正。

原 `corsEnabled:false` 那句被删除——它是未经实测的强断言，且与 dev CSP 的显式放行相矛盾。

## 5. 残余未决

| 项 | 说明 |
|---|---|
| **dev 形态下 Live2D 是否可渲染** | 缺模型无法实测。已在 doc 17 §4.1 留下可证伪的注记与判定方法 |
| **`--model-dir` 的模型从哪来** | 按决策不随仓库分发；团队尚无共享模型包的文档化位置。新用户需自备模型或向团队索取 |
| Linux/macOS 无对应一键脚本 | 仅 Windows 有 `setup-windows.ps1`。Linux 步骤与 Windows 仅 fnm 安装方式不同，doc 17 §3 已覆盖；是否补 `setup.sh` 待评估 |
| `ensure:electron` 仍无根别名 | 仅在出错恢复路径使用，保留 `pnpm -F @cyrene/desktop ensure:electron` 形式；doc 17 §7 已是完整命令 |
