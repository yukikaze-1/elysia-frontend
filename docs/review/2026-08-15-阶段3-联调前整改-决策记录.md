## 3. D1~D4 决策表

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| D1 | webm kind hint 来源 | **MIME 特例回退**：仅 `audio/webm` 时 `video→audio`，其余不变；大小限额仍魔数 sniffKind | 双仓清单均要求 audio/webm+video/webm 分类正确；魔数盲区（EBML 无 audio/video 区分）；MIME 可伪造但 hint 仅提示、后端独立复核，不破 P2-1 限额防线；纯函数最小改动 |
| D2 | REST 门禁载体 | **双轨**：check:contract 扩 REST 段（依赖后端挂载）+ 纯前端定向 vitest | 字段一致性需后端契约源（rest.py 有目标模型）；URL/FormData 语义是纯前端断言、不依赖挂载，CI 稳定；职责分开互不拖累 |
| D3 | 贴图发送纳入 B-02 | **纳入顺带验证**（发送→列表→搜索命中→跳转闭环） | 后端 WS 已接受 stickerId（ws_message.py:714）、前端已发送（real-backend.ts:470）、wire 测试已存在；验证成本低、一次闭环验收 G4 交付 |
| D4 | `localDateToHalfOpenRange` | **删除**（连私有助手与单测） | 修复后唯一调用点消失；保留误导后人以为后端请求仍用它；`isoToLocalDate` 保留供 mock 用 |
| 附 | `audio/webm` 白名单 | 补入 `ATTACHMENT_KIND_MIME.audio` | D1 成立的前置：`kindFromMime` 才能把 audio/webm 归 audio，渲染层播放矩阵/预检/标签与 hint 语义一致；已知行为：渲染层预检按 audio 20MB（此前 file 跳过），Main 魔数路径仍按 video 50MB，渲染层更严，方向安全 |

## 4. 验收口径（B-02）

- **所有分类 tab 搜索结果以「纯文本行 + 「消息」chip」展示**——真实 `SearchMessageItem` 无 `resource`/`kind`/`url`（P2-3），`CyHistoryResultItem.vue` chip 恒为「消息」，非按分类标签；空 snippet 显示「（无文本命中）」兜底。

- **`image_video` 双子流独立游标合并语义**（独立游标 + 顺序合并）记录为通过语义，本批不改算法。
- **「跳回来源消息/分段」正常即通过。**
- **贴图发送 → 搜索命中 → 跳转四步闭环纳入 B-02 验收**：贴图发送（WS stickerId）→ 消息列表展示 → 搜索命中 sticker（真实后端 `category=sticker` 返回 200 非 400）→ 来源跳转。
- 日期筛选按后端自然日契约（`date_from=YYYY-MM-DD`、`date_to=YYYY-MM-DD`、`timezone=IANA`）；`400 INVALID_TIMEZONE` 映射 `INVALID_INPUT`，历史查看器显结构化错误而非伪空态。

## 5. 已知行为

- **audio/webm 渲染层预检差异（I1-评审确认）**：`clientPrecheck`（渲染层）用 `kindFromMime` 预检，`audio/webm` 此前归类 `'file'` 跳过单文件限额，补白名单后按 `audio`（20MB）预检；Main 侧权威路径（`sniffKind` 魔数）对 webm 仍按 `video`（50MB）。即 **audio/webm 在 20–50MB 区间渲染层预检更严、Main 放行**——渲染层 UX 预检为早期反馈、Main 为权威，方向为更严，记录为已知行为，不做算法改动。
- **贴图缩略图 P2-3 后续增强**：历史查看器搜索项仅文本展示（无缩略图）；两条补齐路径（契约增可选 kind/url/stickerId / `queryResources` 通道查 `/api/sessions/{id}/resources`）待后端确认。
- **REST 段类型级比对缺口（M6，后续增强）**：本批 REST 段仅比对字段名/必填性/枚举，不做类型级比对（`has_more: bool` vs `z.boolean()`、`size: int` vs `z.number()` 的类型漂移静默通过）；类型 token 映射（Python 内建类型 → zod 类型）留待后续。
