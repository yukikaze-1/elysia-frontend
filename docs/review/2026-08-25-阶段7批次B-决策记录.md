## 4. 主会话裁决（credentials 不纳入统一层——本批关键裁决）

**裁决：`createCorruptIsolation` 统一层只由 settings / session-store 采用，credentials（CredentialStore / 安全凭据）不纳入。**

依据：
1. **fail-closed 不拉平**——缓存损坏统一层的语义是「隔离损坏副本 → 重建默认 → fail-open 继续运行」；凭据的安全语义恰好相反（fail-closed：损坏/形状失败 → 拒绝启动/拒绝使用该凭据，绝不「重建空凭据」）。统一骨架要求各 store 声明语义，但**凭据若走 `isolate` 的「备份 + 重建默认」会关闭 fail-closed**，引入安全回退，违反本批纪律。
2. **不为密文增备份副本**——凭据为 `safeStorage` 加密块；`.corrupt-*` 备份会为明文密钥/密文增加磁盘滞留副本（即使密文也扩大攻击面），与「敏感面零正文」「不落盘备份」纪律冲突。
3. **5 参构造注入不划算**——`createCorruptIsolation` 的 `{ isolate, dropInvalid, pruneCorrupt }` 接口依赖注入（logger/audit/countDiagnostic/safeRoot/realpath）为 settings/session-store 的损坏处理定制；将 CredentialStore 纳入需为它扩展一套独立的 fail-closed 副本语义（隔离后必须 fail-closed 而非重建），构造注入成本高、收益低。
4. **既有 CredentialStore 自身已 fail-closed**——阶段 0/1 整改批次 A（FE-S1-P1-03）已落地 CredentialStore 有序退出 + 损坏重建不污染（`EMPTY_FILE` 工厂化），凭据损坏的处理已由既有逻辑承载，不重复造统一层。

**记录**：credential-store.ts 在本批**不修改**（Task 5 brief 决策单列项，落地为「不纳入」）。settings.json 的篡改/形状失败仍走既有 corrupt 隔离回默认 fail-open（doc 06 §8.1 迁移注记与 doc 07 N-8 注记维持）。

## 8. 已知限制与接受档

1. **崩溃二次触发无风暴抑制**：`render-process-gone` 在 reload 后若再崩，会再触发一次 reload——本批**不做崩溃风暴抑制**（每次崩溃 reload 一次；防无限 reload 由 Main 侧「reload 后检查 webContents 是否存活 + crashMarker 一次性清空」兜底）。若连续崩，用户可到连接面板手动处置。
2. **`getLastCrash` 一次性**：读一次后清空 marker——防 reload 后每次启动都提示（除非再次崩溃）。崩溃 marker 为**内存态**（模块级变量），进程重启即失，不做持久化（避免事故后永远提示）。
3. **GPU 崩溃不自动 reload**：GPU 崩溃留痕（`gpu:crash`）不 reload——Live2D 层经 `webglcontextlost` + `restoreLostContext`/`rebuild`（阶段 5 批次 C 已实现）间接恢复；若 GPU 反复崩导致 Live2D 不可用，7C 性能批再评估。
4. **崩溃提示非实时 push**：崩溃提示是 reload 后由新 Renderer 经 `getLastCrash` 读取显示，**非崩溃瞬间的实时 banner**（renderer 已死收不到 push——安全 H-2 定案）。
5. **Renderer 全局错误兜底不做**：本批**不做 UI 级 error boundary**（只做进程崩溃）；JS 异常兜底保留为观察项——若 7B 实测 renderer JS 异常多，7C/D 再评估。
6. **`.corrupt-*` 备份含聊天正文**（尤其 message-cache-v1.json）：经 `pruneCorrupt` 有界保留（只留最新一份），**不纳入日志/审计/诊断导出**（doc 01/07 注明）；settings 备份仅含 app 设置，无正文。
7. **`isolate` 的 `rename(...).catch(()=>{})` 静默吞错**：rename 失败时 `countDiagnostic` 仍记 1 且返回 dest——经 Task 5 re-review 评估为**可接受**（既有语义被制度化；生产调用方均忽略返回值；输入文件刚被 `openSafeFile` 读过，同目录 rename 极难失败；后续 atomicWriteFile 会覆盖损坏文件）。
8. **`assertContained` 用 `startsWith(safeRoot)` 前缀而非目录边界**：`isIsolate` 的 file 参数在 settings/session 均为固定常量，非攻击者可注入路径，无真实逃逸面；真实 containment 权威在 `openSafeFile`，此处仅防御纵深（建议非阻断：改为 `real===safeRoot || real.startsWith(safeRoot+sep)`）。
