## 2. 实施前/评审过程决策（按推荐定案，最终报告汇报）

### 2.1 媒体代理协议统一（G3 × G4 交叉，评审 P1-2/P2）
- **决策**：统一到 **`cyrene://renderer/__cyrene-media/{mediaType}/{id}`**（mediaType ∈ {attachment, sticker}）。
  - G3 附件走 `attachment/{attachmentId}`（签名 URL + Range/206 + 过期重签）；
  - G4 贴图走 `sticker/{stickerId}`（静态公开 URL `/static/stickers/{stickerId}.png`、stickerId 白名单 `^st_[A-Za-z0-9-]+$`、MIME 白名单 image/png、无签名、1MB 大小上限）。
- **理由**：复用既有 `cyrene://` scheme 注册（无新 scheme/特权面）；prod 同源（cyrene://renderer）img-src `'self'` 即放行；继承 G3 导航 deny + `Sec-Fetch-Dest: document` 防护；避免两套代理并存与迁移成本。
- **落实**：G3 spec（dab8d72）声明通用机制 + G4 为消费方；G4 spec（d3fac06）D9 复用子路径；G3 贴图路径对齐 `.png`（d30dd50）。

### 2.2 草稿与滚动锚点持久化归 Main（G2 D1）
- **决策**：草稿 + 滚动锚点经新 IPC（`persistSession`/`hydratePersistence`/`cacheMessages`）归 **Main 版本化 JSON** 持久化，Renderer 只持内存态。
- **理由**：信任边界（docs/07 §1，Main 是持久化边界）；草稿为敏感用户输入；配额权威执行；复用 safe-open/atomicWrite 地基。

### 2.3 虚拟列表自研轻量窗口化（G2 D3）
- **决策**：估高 + ResizeObserver 实测 + 前缀和二分，**不引三方库**。
- **理由**：项目最小依赖；窗口数学纯函数可单测；`content-visibility:auto` 记录为兜底。

### 2.4 loadOlder 有序二分插入替代 append（G2 P0-1 修复）
- **决策**：`upsertMessage` 改为 `(createdAt, messageId)` 升序有序插入（新 key 插到第一个「不早于自己」key 前，已存在原位替换）；loadPage 合并前防御性排序；离线水合/切换前强制排序。
- **理由**：现有 upsertMessage 对新 key 一律 `order.push()` 追加末尾，`before` 页会被推到底部导致向上加载错乱（评审置信 95）。

### 2.5 附件状态机省略 `uploaded` 瞬态（G3 P2-2 修复）
- **决策**：`uploading → 发送编排 → 清出队列`，不驻留独立 `uploaded` 态。
- **理由**：docs/06 §7 枚举（selected|validating|ready|uploading|failed|cancelled）无此态；上传成功不驻留独立状态。

### 2.6 历史查看器资源缩略图设计缺口（G4 P0-1，超出现有 spec）
- **问题**：`frontend_contract` `SearchMessageItem` 为 camelCase `{conversationId, messageId, responseId?, segmentId?, role, timestamp, snippet}`，**无 kind/url/stickerId**；原 spec 假定 search 结果含资源元数据（缩略图/来源跳转），契约实际不含。
- **决策（实施前）**：历史查看器搜索项**仅文本展示**（chip 由当前查询 category 派生，跳转仍可用）；`ConversationResource` 领域类型保留作参考。两条补齐路径待后端确认：① `SearchMessageItem` 增可选 kind/url/stickerId（契约变更）；② 新增 `queryResources` 通道查 `/api/sessions/{id}/resources`（依赖 G3 签名端点，G4 不实施）。
- **备注**：已在 G4 plan 标注为 spec 开放项，最终报告汇报。

### 2.7 CSP「dev 三处 vs 两处」口径（G4，plan 已按正确）
- **决策**：贴图经 `cyrene://renderer`（同源），prod `img-src 'self'` 即放行、**不改 `protocol/csp.ts`**；dev（http://localhost）仅 `config/dev-csp.ts` + `renderer/index.html` meta **两处** img-src 追加 `cyrene:`（csp.ts 不参与 dev AND 交集）。
- **备注**：spec §5 D9 决策表「dev 三处追加 cyrene:」为残留不一致（源自轮次 1），以 §4.6 两处为准，最终报告汇报修 spec。

### 2.8 各 spec/plan 评审修复的其余关键决策（摘要）
- G1：布局记忆走 Renderer localStorage（`cyrene.layout.v1`）而非 Main 配置（D6，需实质修订 docs/06 §8.1）；双 override 兜底按优先序回退；toggle 按目标态设置 + override 置位；首帧 viewportWidth 用 window.innerWidth 播种。
- G2：离线切换 `activateLocal`（绕过后端 activate，disconnected 才可用）；IPC 单条大小上限 `MAX_IPC_MESSAGE_BYTES=4MiB`（docs/07 §6.3）；50 会话淘汰经 `evictedConversationIds` 一次性通知（不静默）；connected 分支缓存不进入 messageStore。
- G3：上传取消经 `AbortSignal` 接入后端（非 no-op）；粘贴 pathless 文件走 bytes 通道；每文件 kind（后端魔数权威）；历史附件 name/size 由 ContentPart 承诺；映射层（rest-mapper）为媒体缺失真实缺口（schema `content: unknown` 不改）。
