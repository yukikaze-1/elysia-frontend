**日期：** 2026-08-29（Asia/Shanghai）

## 1. 改版目标

当前输入区 5 个同权重按钮（附件/录音/实时/转写/表情）无层级、易混淆，尤其普通录音/语音转录/实时语音三者难分辨。本次：

1. 减少按钮拥挤感；
2. 按功能层级重新分组（**添加内容 / 文本输入 / 语音输入 / 模式入口**）；
3. 突出高频；
4. 让「实时语音对话」从普通输入独立出来（模式入口，非单次输入）；
5. 提升首次可理解性。

**用户拍板的决策：**
- 语音转录/普通录音**合并为统一 🎙️ 入口**（转录为主键 + 下拉菜单切录音）；
- 实时语音**移出主行、独立胶囊按钮**（输入区外）；
- `+` 附件**改为弹出菜单**（按 accept 分类）；
- 常驻控件收敛为 **6 个**：`＋ 😊 输入框 🎙️ ➜ 🎧`；
- 范围**聚焦输入区**：不动 CyRealtimeBar 内容 / CyEmojiPicker 定位 / 附件队列。

## 2. 目标布局

```
┌──────────────────────────────────────────────────┐
│ [＋▾] [😊]  输入消息…              [🎙️▾] [➜]   │  ← composer-box（输入）
└──────────────────────────────────────────────────┘
                           [🎧 实时语音]            ← 独立胶囊（框外，模式入口）
```

- **输入行（composer-box）**：`＋▾` `😊` textarea `🎙️▾` `➜`
- **框外模式入口**：`🎧 实时语音` 胶囊，位于输入区下方独立一行，视觉上略高于普通小图标按钮（用户建议「核心亮点略突出」）。

### 语义映射
| 区域 | 控件 | 语义 |
|---|---|---|
| 左侧 | `＋▾` `😊` | 添加内容（附件 / 表情包） |
| 中间 | textarea | 文本输入 |
| 右侧 | `🎙️▾` `➜` | 语音输入（转录默认）/ 发送 |
| 独立 | `🎧` | 进入实时语音模式 |

## 3. 各键位交互设计

### 3.1 `＋▾`——附件入口（弹出菜单，按 accept 分类）

- 主键 `＋` 与下拉箭头 `▾`：点击画布内弹出小菜单。
- 菜单项：**图片** / **文件** / **音频** / **其他**，各带 accept：
  - 图片 → `accept="image/*"`
  - 音频 → `accept="audio/*"`
  - 文件 → 无 accept（全类型）
  - 其他 → `accept` 按需/暂无固定
- 选中后开对应 `<input type="file" accept="...">`，`File[]` 经 `attachmentStore.addFiles`（现有，不改 store）。
- **实现注**：单 input 的 accept 在点菜单后动态切换，或预置多个 `accept` input（原生更稳）。`addFiles` 已接收 `File[]`，无需改。

### 3.2 `😊`——表情包入口（现有，仅锚点移入）

- 保留 `aria-label="Emoji 与表情包"`，现有 `showPicker` 弹窗逻辑不变。
- 仅将其从独立行（上批已移入 box）调整为与 `＋` 相邻的左侧组。

### 3.3 `🎙️▾`——统一语音入口（转录主键 + 下拉菜单）

**这是本批最大交互变更，含手势区分。**

- **主键 `🎙️`（转录，默认）**：`pointerdown` 开始转写（hold），`pointerup` 提交（final 进草稿）。沿用现行 `startDictation` / `stopDictation` / `cancelDictation` hold 语义与 pointer 链（`onDictationPointerDown`/Move/Up/Cancel）。`aria-label="输入法转写（按住说话）"` 保留——测试红考依。
- **下拉箭头 `▾`**：与主键分离的可点区域。点击弹出菜单：
  - **语音转文字**（默认，选中高亮）
  - **录制语音消息**（→ 进入 toggle 录音模式，下文）
- **手势冲突回避**：主键=hold（转录），箭头=click（菜单）。二者是**两个响应区域**，不共用 pointer 手势，从而避免「同一按钮 hold 与 toggle 冲突」。
- **录音**：菜单选「录制语音消息」后，`＋` 不参与——录音状态经 `CyVoicePending`（现有）呈现——录音点开/点停 toggle 在**独立的录音胶囊**或**菜单选中后的 on/off 态**。设计倾向：菜单选择仅作为「录音」入口的发现路径，实际 toggle 在录音胶囊（选中后胶囊出现）。这保留录音的 toggle 语义，同时不污染转录 hold。

**关键权衡提示**：语音转录是**hold（按住→进草稿）**，录音是**toggle（点开/点停→音频消息+确认发送）**，二者手势天然相反。本方案通过「转录 hold 主键 + 箭头菜单」化解——主键只做转录 hold，录音经菜单进入独立 toggle 态。**代价**：录音从常驻按钮变为菜单入口，可发现性显著下降（阶段 6 曾用真实能力）。这是产品权衡，已获用户拍板。

**定稿决策（2026-08-29）：**
- **主键/箭头分离**：主键（转录 hold）与下拉箭头形成为**两个独立可点区域，中间留 gap**。`pointerdown` 手势只绑定主键，箭头只响应 `click`（不响应 pointerdown），转写 hold 起点远离箭头，避免误触菜单。
- **录音态呈现**：菜单选「录制语音消息」后**直接进入 toggle 录音**（麦克风键变红 + 计时），停止后复用现有 `CyVoicePending`（待发送条 + 确认发送）。与现有录音语义完全一致。
- **🎧 视觉**：accent 填充（高辨识），凸显「实时语音 = 核心模式入口」。

### 3.4 `➜`——发送（现有，语义不变）

- 现有 `canSend`、`send` 语义不动。`aria-label="发送"` 保留。

### 3.5 `🎧 实时语音`——独立胶囊（模式入口，框外）

- 位于输入区下方独立一行（非 composer-box 内）。`aria-label="实时会话"` 保留（测试红考依）。
- 点击 → `startRealtime`。`mode==='realtime'` 时 `CyRealtimeBar` 仍 `v-else` 替换整个输入区（现有逻辑，不动 CyRealtimeBar 内容）。
- 视觉上略高/带 accent，标注为模式入口而非普通图标。

## 6. 测试影响（§9）

改 aria-label / 新增交互，下列用例需同步：

| 用例 | 位置 | 影响 |
|---|---|---|
| `普通录音` | electron-voice.spec:95,160,342,366 / cy-chat-input.spec:54 | 转录主键+菜单后，「普通录音」成为菜单项 aria-label；保留仍可命中 |
| `输入法转写（按住说话）` | electron-voice.spec:194 | 主键 aria-label 保留 |
| `实时会话` | electron-voice.spec:211,219,351 | `🎧` 胶囊 aria-label 保留 |
| `停止录音` / `确认发送` | electron-voice:126,133... | 录音 toggle 态不变，保留 |
| 转写浮层 `.cy-dictation-hint` | electron-voice:197 | hold 链不变，保留 |

**结论**：若保留各 aria-label（仅改视觉位置/容器），多数测试**无需改**；需新增的是「🎙️▾ 下拉菜单」的可达性测试（可选）与「＋▾ 附件菜单」分类测试（可选）。核心链路由不变。
