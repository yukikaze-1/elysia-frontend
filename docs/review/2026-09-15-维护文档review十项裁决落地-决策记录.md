## 4. D4-1：本地风险按参数重算（补代码）

**此前状态（review 认定，复核成立）**：`tool-service.ts` 的授权判定只看 `permissionMode` /
`grants.matches` / 豁免；审计里的 `riskLevel` 直读注册表常量 `tool.localRisk`；
`real-backend.ts` 组 `DesktopToolRequest` 时**丢弃** `frame.riskLevel`/`permissionRequired`/`approvalAuthority`。

**落地**（`tool-policy.ts` 新增两个纯函数）：

```text
computeLocalRisk({ base, reported, args, realPath, blacklisted, sandboxRoots, platform })
  1. blacklisted            → 'high'        （黑名单压过一切）
  2. reported 归一后与 base → 取较大者       （只升不降：绝不因后端说低而降低）
  3. 路径类工具带 content    → 'high'        （覆盖写比新建破坏性更大；此前只看工具名）
normalizeReportedRisk(raw)：三档原样；缺省 → undefined；**未知/畸形 → 'high'**（不静默降级、不忽略）
```

- `ToolRecord` 增 `riskLevel`；审计 `tool:decision` / `tool:request-received` 改取重算值
  （`decide` 与 grant 命中两处不再直读注册表常量）；`tool:request-received` 同时落
  `riskLevel`（本地）与 `backendRiskLevel`（归一后上报值）两栏，可解释「为什么是这个等级」。
- `PublicToolEvent` 增 `riskLevel`（三档枚举）随 `tool:event` 下发，供权限窗/卡片解释；

- **授权结果未改**：判定顺序仍是 `automatic → grant 命中 → selected-set 豁免 → prompt`。

**测试**：`tool-policy.spec` 32（+15：归一 / 只升不降 / 畸形归 high / 黑名单 / 参数升级 / 沙盒空集）、

## 6. D4-15 / U-9：域名黑名单接线 + 沙盒目录层（补代码）

### 6.1 域名黑名单

`isDomainAllowed` 此前**只有定义与单测、生产 0 调用**。现 `real-backend.ts` 新增
`assertBackendOrigin()`，在**三个带 Bearer 的直写 fetch**（`uploadAttachments` /
`uploadToolAttachment` / `readToolAttachment`）发请求前断言「目标 origin 命中允许集」；
允许集 = `serverOrigin`（配置端点，反代 path 不计入 origin）∪ `options.allowedDomainOrigins`
（新增选项，缺省空）。失败**拒发**（不降级、不改写目标）。

> **如实声明边界（写进代码注释与 doc 04 注记，勿高估）**：三个调用点的 URL 都由 `serverUrl`
> 自身拼出，故断言在**当前**调用形态下**恒真**。它的价值是①把「domain 黑名单」从零调用变为
> 唯一且显式的收口点；②给后续任何改用「非自身拼出的 URL」的取值留一处 fail-closed 闸门
> （例如将来按后端返回的绝对上传地址直传）；③端点畸形时拒发而非默默打空请求。
> **它不是**「已挡住一次真实攻击」的 SSRF 防护。

### 6.2 沙盒目录层

空串根忽略（不因畸形配置放行一切）；`tool-service` 增注入面 `deps.sandboxDirectories`。
**F-06 拍板值仍为空集** ⇒ 对空集生效：零预授权，没有任何路径因「落在沙盒内」而免确认，
**不产生新的自动执行路径**（这是本次落地的硬约束）。

**测试**：`real-backend.spec` +2（守卫在路径上：放行形态 fetch 发生 / 未连接形态拒发且未发生；
