# 多角色旧数据不迁移决策记录

**决策日期：** 2026-09-08
**适用范围：** 多角色 Stage H 开发与真实联调
**前端基线：** `elysia-frontend@7fb934f`
**后端基线：** `elysia-agent@65295a90`（其中 `575b430f` 执行迁移骨架删除）
**状态：** 已定案，待按本决策准备干净联调数据

## 1. 决策

项目仍处于开发阶段，现有数据无保留价值。本轮不实现、不执行旧数据迁移：

- 后端不为旧 session 生成 legacy character instance；
- 不复制旧 `character_state`、旧 character versions、旧 LTM 或 pending 数据；
- 前端不转换旧会话缓存、旧角色摘要或旧 Live2D 设置；
- 联调/部署前显式清理开发数据，从新 schema 创建新数据；
- 应用启动时不增加隐式清库或迁移逻辑。

## 2. 仍然保留的兼容边界

“不迁移数据”不等于删除所有协议防护。以下能力仍保留：

- `character_profiles` / `character_state_stream` 缺失或为 false 时的 capability gate；
- raw REST/WS 角色字段可选形状及能力开启后的运行时 fail-closed 守卫；
- 缺角色身份时不根据名称、头像、Live2D 或消息内容猜测身份；
- 本地设置/schema 容错逻辑，但它们不构成旧数据可用性承诺。

后端契约中的 `createdBy: migration` 可作为保留枚举值继续存在；它不表示当前存在迁移任务或会产生该类记录。

## 3. 联调前置

1. 清理精确的开发应用数据库，不触碰 MongoDB 系统库或其他项目数据库。
2. 使用干净的 Electron userData/测试配置，不将旧缓存结果当作新后端数据。
3. 完成首次连接后，所有新建 session 必须带完整 `characterId + characterInstanceId + characterRevision`。
4. `pinned` revision policy 使用后端新数据受控夹具验证，不通过迁移旧会话制造。

## 4. 影响

- 删除 FE-G 中的旧会话/旧缓存/旧 Live2D 设置迁移交付项；
- 不修改 `character-contract-v1` 的 REST/WS 字段；
- 不扩大阶段 8、任务中心或 Neo4j 范围；
- 真实联调证据必须来自清理后的新数据，不用 Mock 或旧缓存代替。
