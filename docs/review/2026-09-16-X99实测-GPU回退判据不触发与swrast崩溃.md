## 1. 结论（一句话）

**产品侧那条自动回退在这台机器上不触发，而 GPU 进程在同一次运行里崩了三次（内核侧 swrast 段错误）。**
此前"判据覆盖不到我们真正观测到崩溃的那一档环境"是**由 `/dev/dri` 的存在推断**出来的；本记录把它变成
**同一次运行内的直接观测**：`disabled:false` 与 `segfault in swrast_dri.so` 并存。

**所以这台机器不是"无 GPU 环境"**：设备节点齐全、两块真实显卡、驱动已加载。它是
`XDG_SESSION_TYPE=tty` + `DISPLAY` 未设 —— **有硬件、没有可用显示会话**。

## 3. 期望 vs 实际（脚本第 3/4 节）

- 由规则推出的期望（脚本第 3 节逐字）：`期望 disableHardwareAcceleration=0`（不干预）。
- 应用实际记录的判定（`~/.config/Cyrene/logs/app.log`，本次运行那一行）：

```json
{"ts":"2026-09-16T10:25:17.145Z","level":"info","logger":"main","code":"gpu:runtime-mode",
 "fields":{"disabled":false,"mode":"auto","source":"default","platform":"linux"}}
```

⇒ **期望与实际一致：判据没有触发**（`source: "default"`，不是 `no-device-node`）。

- 同一进程窗口内的 GPU 崩溃（stdout，逐字，3 次）：


- 内核侧（`journalctl -k`，逐字，3 条，同一指令偏移）：

```text

9月 16 18:25:28 yomu-X99 kernel: electron[367521]: segfault at 171400000010 ip 000078328270f82b ... in swrast_dri.so[...] likely on CPU 15
```

- 启动形态与结果：无显示会话 ⇒ 脚本用 `xvfb-run -a` 包一层，以
  `CYRENE_TEST_HARNESS=1 CYRENE_WINDOW_MODE=silent CYRENE_TEST_APP_DATA=…` 启动（silent：不显示窗口、
  不抢焦点、不弹原生对话框）；**退出码 124 = 25s 到点被结束**，即应用在该窗口内**没有自行退出**。

## 4. 该怎么读这个结果（不夸大也不缩小）

- **能主张**：① 判据在 X99 上按"设备节点存在"的语义**正确地不触发**（实现与设计一致）；
  ② 在该机上、以当前代码、无显示会话时，**GPU 进程会持续段错误**（与 2026-09-12 记录的同一族、
  同一 `swrast_dri.so` 指令偏移）；③ 该次运行应用存活到窗口结束——但这**不等于"没问题"**：
  Chromium 的既有行为是重试耗尽后 `FATAL: GPU process isn't usable. Goodbye.` 主动杀掉整个浏览器进程
  （2026-09-12 那次的形态），本次只是没走到那一步。
- **不能主张**：① 不能主张"无 GPU 的 Linux 已被验证支持"——本机**不是**那一档，那一档仍未取证；
  ② 不能主张回退"没价值"——它对**真的没有** `/dev/dri` 的环境（容器/精简 VM）仍然正确触发，
  只是**覆盖不到 X99 这一档**；③ 不能把 CI 的绿色读作产品规则生效——CI 一直绿靠的是测试脚手架
  注入的 `--disable-gpu`（`tests/integration/helpers/app.ts`、`verify-artifact.cjs`）。

## 5. 由此得到的下一步候选（**未实现，需决策**）

要在 X99 这一档上真正收敛，需要换一套判据。两个候选方向（都属**新机制**，不是缺陷修复）：

1. **判"会话/显示可用性"**：无 `DISPLAY`/`WAYLAND_DISPLAY`（或 `XDG_SESSION_TYPE=tty`）时也视同
   "无可用 GPU"。代价：会改变**有 GPU 但刻意无头运行**的场景（CI/服务端渲染类用法），需确认那是
   期望行为；且它把"无头"与"渲染不可用"绑定，属较强假设。
2. **按事件自救**：监听 `child-process-gone` 的 `type: 'GPU'`（本仓**已有**这个处理器，现在只记审计
   不重载），累计到阈值后带 `--disable-gpu` 重启一次。代价：新增一次重启语义与"何时重置计数"的规则，
   且重启会丢失当前未落盘状态。

在决策之前，**不得**把 doc 09 §8 的支持边界读作"已解决"。
