## 4. 实施期两个 Ruling（plan 字面与运行时语义冲突，已实证并修复）

### Ruling A（Task 1）：`seedHistoryCount` 字段初始化器在原生 class fields 下运行时非法

plan §4.3.1 字面要求字段初始化器 `private readonly seedHistoryCount = options.seedHistoryCount ?? 0`（声明在 `messageRecords` 之前），`seedMessages()` 才能读到。本仓 TS target=esnext（原生 class field，`useDefineForClassFields` 默认 true），**字段初始化器先于构造函数体执行、且作用域内没有 `options` 形参**。已实证三种情况：

- 普通形参 → `ReferenceError: options is not defined`（vitest 首次 RED 即此）；
- 参数属性 `constructor(private opts)` → 原生 class field 下字段初始化器执行时 `this.opts` 仍为 undefined（tsc emit 实证 `TypeError: Cannot read properties of undefined`）；
- 仅 `useDefineForClassFields:false` 下参数属性可先于字段赋值（但 esbuild/electron-vite 均保留原生 class field，运行时路径不成立）。

**定案：** 按 plan 字面不可实现，无「既读 `options` 又是字段初始化器」的方案。改为**构造体内按序赋值**——`this.seedHistoryCount = options.seedHistoryCount ?? 0` 先于 `this.messageRecords = this.seedMessages()`，字段**声明顺序保留**（`seedHistoryCount` 声明在 `messageRecords` 之前）。`seedMessages()` 仍能读到正确 count（满足 spec §4.3.1 意图）；缺省时 seedHistoryCount=0 → 5 条默认 seed 不变。该模式与本仓既有风格一致（frame-mapper.ts / real-backend.ts / session-store.ts 均为构造体内赋值或参数属性）。**误判代价：** 若评审者把此偏差当缺陷要求回退到 plan 字面写法，会在运行时崩。

### Ruling B（Task 3）：`launchWithSize` 的 `app.evaluate` 闭包变量不随 Playwright 序列化进入主进程

plan §4.4 字面写 `app.evaluate(({ BrowserWindow }) => setContentSize(w, h))`，其中 `w/h` 是测试函数外层闭包变量。Playwright `electronApp.evaluate` 把回调**按源码序列化**进 Electron 主进程执行，**闭包变量不携带**，在 main 进程作用域解析为 `ReferenceError: w is not defined`（3/3 用例失败实证）。

**定案：** 改为显式第二参传 `{w, h}`——`app.evaluate(({ BrowserWindow }, size) => setContentSize(size.w, size.h), { w, h })`，与仓库既有 `trust-boundary.spec.ts` 同款 `(pageFn, arg)` 模式。纯机械修正，brief 意图（setContentSize 固定 viewport）不变，代码内已留注释。**误判代价：** 若评审要求回退闭包写法，测试必崩。

## 5. 锚点测试设计要点（spec 评审补强）

- **渲染序 ≠ store 序：** store 数组是 `sortKey` 升序（loadMore 合并后升序重排），但组件 `groupedItems` 按本地自然日**降序**重组渲染——最新日期组在最前、组内升序。锚点补偿作用于渲染后 DOM，锚点测试初稿据此修正：加载前先滚到**跨页边界日期组**（该组第一页只含部分条目，第二页补入更旧条目按组内升序前插组首），捕获首个可见项为锚点，而不是在 store 序上推导。跨页边界日期组前插是 §4.2 手动补偿的唯一真实扰动点，测试显式瞄准。
- **锚点精确偏移 ≤1px 断言：** 捕获锚点项的 `offsetTop`（`el.getBoundingClientRect().top - 容器.getBoundingClientRect().top`），loadMore 后同 `data-hit-id` 项的新 offsetTop 与捕获值差 ≤1px。无补偿时边界组前插 ~10 条 → 偏移 +~650px，断言失败。
- **`overflow-anchor:none` 必要性：** Chromium 原生滚动锚定默认 `auto`，会在 DOM 插入时独立调整 scrollTop 把可见项拉回原位。若不禁用，手动补偿在 `nextTick` 后测到偏移已≈0 而变成 no-op，step 8 断言被原生机制满足——**即使补偿逻辑被删/写坏测试照样绿，对 §4.2 假绿**。关停后手动补偿成为唯一调整机制，step 8 只反映 §4.2 是否生效。
- **`parseMockHistoryCountEnv` 语义：** `undefined`→undefined（不装大 seed）；正整数→原值；`0`/负数/NaN/非整数→**默认 120**（「大」语义兜底，且 `'0'` 不允许产出空 seed——否则与「≥100」测试前提冲突）。
