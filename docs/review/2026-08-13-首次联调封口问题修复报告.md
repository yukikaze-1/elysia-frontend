## 3. 协议与错误链

### 3.1 ACK 判别联合

`user_message.ack` 现在直接表达后端不变量：

- `accepted`：`messageId` 和 `clientRequestId` 必须非空，且不允许 `error`；
- `rejected`：`messageId` 必须为 `""`，`clientRequestId` 允许为空（覆盖“请求 ID 本身缺失”的契约拒绝回显），`error` 必填；
- rejected `error.retryable` 必填，并完整接收可选 `details/retryAfterMs`；
- raw schema 使用 `.strict()`，未知字段不会被无声接受。

### 3.2 ErrorMessage 与公开诊断字段

raw `error` 帧新增并保留：

- `clientRequestId`；
- `retryAfterMs`；
- `details`。

rejected ACK 与 error 帧会把 `clientRequestId/retryAfterMs/idempotencyDurable` 沿 IPC 错误信封传到 Renderer。原始 `details` 只保留在 Main 内的 `backendDetails`，不会整体穿过 `contextBridge`；跨边界仍只放行明确白名单，避免把未知后端诊断或敏感内容暴露给 Renderer。

## 4. 会话初始化恢复能力

`conversation.store` 的列表操作现在返回明确成功/失败结果。`onConnected()` 只有在列表成功后才写入当前连接的 `initializedFor` 并置 `ready=true`；列表失败时保持未就绪和可见错误，因此同一 `connectionId` 的后续连接事件可以重新初始化。

同一连接初始化尚在进行时，重复调用会等待同一个 Promise，避免重复请求列表。回归测试覆盖“第一次列表失败、同一连接第二次成功”的完整状态变化。

## 5. 字段级跨仓契约门禁

`pnpm --filter @cyrene/desktop check:contract` 现在执行三层检查：

1. 后端 Schema 与前端当前 WS v2 子集的 type 覆盖；
2. 扫描后端契约源生成的非 legacy `ws-v2-*.jsonl`，逐条调用 `parseRawFrame()`；
3. 对解析结果与原始 JSON 做深度相等比较，任何字段被拒绝、默认改写或静默 strip 都会非零退出。

生成帧没有穷举可选字段时，脚本还会依据后端 Schema 构造 `ErrorMessage` 与 rejected ACK 探针。本轮实际结果为：

```text
WS v2 type 覆盖: 11/11 通过;
字段级帧 44 条完整保留;
phase3+ 帧 27 个有意滞后(warn)
```

raw schema 结构变化后，11 份 fixture manifest 的 `schemaHash` 已同步为当前指纹；`verified/backendCommit` 没有被提升或伪造。
