## 4. 主会话裁决（§4C 流式增量合并降级观察项——本批关键裁决）

**裁决：本批不做 §4C 流式增量合并，降级为观察项。**

`StreamAccumulator.toAssistantSegments()` 每 delta 全量 `.map().filter().sort().map()`（重排全部分段）。§4B 缓存已解决「流式重复 re-parse」主瓶颈（CyMarkdown 对 source 未变的 segment 不再 re-parse）；§4C 剩余的「每 delta 全量 sort」成本极低（segment 数通常≤5，O(k log k) 可忽略），而实现需复杂纪律（定稿不可变 + authoritative 覆写失效 + Vue 响应 + `(segmentIndex, deltaSequence)` 排序复刻），风险/收益不成比例——**用户 2026-08-26 拍板降级观察项**。视图感知暂停（视口外 segment 不 re-parse）同样记观察项（范围增强，YAGNI 风险）。

**若未来重访**需满足 spec §4C 已列纪律：segment「定稿」按「不会再被变更」判定（非 completed）；定稿对象不可原地变更（变更即建新对象保 Vue 响应）；`authoritative` 覆写时缓存失效重建；增量维护复刻 `(segmentIndex, deltaSequence)` 排序。

## 8. 已知限制与接受档

1. **流式增量合并不做（§4C 降级观察项）**：§4B 缓存已解决「流式重复 re-parse」主瓶颈；§4C 剩余每 delta 全量 sort 成本极低（segment≤5）但需复杂纪律，风险/收益不成比例。视图感知暂停（视口外 segment 不 re-parse）同样记观察项——两者留待重新评估。
2. **长会话内存有界测量驱动**：本批测量 suite 仅断言 JS 堆上限告警（非硬失败）——若实测 byId/cache.snapshots/historyViewer.items 无病态增长，记观察项不强行加上限；仅当测量证明确有问题才纳入。
3. **Live2D collapse 不 dispose**：资源常驻但 rAF 停（expand 无需重载，恢复快）。CPU/GPU 下降幅度非「释放资源级」，是「停渲染级」——测量验证的是 rAF 停（7C 复核），非资源释放。
4. **历史查看器虚拟化后焦点陷阱/锚点**：锚点恢复仅覆盖已加载行（虚拟化后未加载行无 DOM，锚点 data 层计算恢复——接受档）；Tab 焦点陷阱查询 overlay 全量 focusable（虚拟化只影响 item 行是否挂载，最后 focusable 仍为 footer「加载更多」）。
5. **性能阈值**：松阈值×1.5 防 CI 抖动（本批 DOM 有界为结构性硬上限 ≤60，非基线数值×1.5）；堆告警采样多点取稳定值仍无法完全消除 JIT/GC 抖动。`performance.memory` 为 Chromium 非标准 API（弃用方向）——若 Electron 升级移除则门禁退化为仅 DOM 节点断言 + 告警注记（记观察项）。
6. **CyMarkdown 缓存为敏感文本派生副本（安全 M-1，接受档）**：模块级 `Map<source, html>` 是 chat content 的二次常驻副本（renderer 堆内、post-sanitize、仅随会话切换清空）。不跨信任边界、不进日志/导出，但属敏感文本额外驻留——量级以「会话内渲染分段总数」为界，非新病态面。缓存键并入 DOMPurify 配置版本（当前静态常量故仅记观察项）。
7. **100 分段全量呈现**：行内 segment 无条件渲染（不经虚拟列表窗口裁剪）——为正确性（全部 N 段可见）而非有界；真实「有界」由行级虚拟化（`.cy-vlist-row`≤60）承担。观察项「视图感知暂停」在未来重访。
8. **verify:sensitive allowlist 新增 2 条目**（Task 6 门禁）：spec/plan 新落文档触发 `base64-long-string`（模块导入串 + git add 串 + 虚拟行/估算函数标识符，均为可读路径/标识符长串，非高熵秘密）——按 fail-loud 纪律逐行人工核对补条目。
