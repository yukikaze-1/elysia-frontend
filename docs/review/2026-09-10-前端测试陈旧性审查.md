# 前端测试陈旧性审查（2026-09-10）

**记录日期：** 2026-09-10

**文档状态：** 生效中

**审查范围：** `apps/desktop/tests/unit/**`（208 文件 / 2735 用例）+ `apps/desktop/tests/integration/**`（22 文件）

**审查动机：** 功能侧整改完成后（见[修复决策记录](2026-09-10-三项产品缺陷与集成孤儿进程修复-决策记录.md)）复核「测试是否还在说真话」——即是否存在**仍然全绿但已不能失败**的用例。

**判定口径**（六类，只有这几类算「陈旧」）：
1. 断言的行为已不存在（选择器/导出/字段/通道被改名或删除，用例只因断言了附带物而继续通过）；
2. 断言显著弱于用例名或注释的声称（如声称「拒绝/保留/失败」却只断言 `toBeDefined()`/`not.toThrow()`）；
3. 同义反复 / 自证（断言测试自己刚喂进去的字面量，或 mock 掉了被测对象本身）；
4. 重复覆盖（同一边界已被同套件另一用例钉住，不新增边界）；
5. 已删除功能或不可达路径的用例；
6. 注释/标题叙述的是已被推翻的设计决策。

**不算陈旧**：有记录的 `it.fails` 环境 canary、平台条件跳过、用例偏少/覆盖不足、命名风格偏好。

---

## 1. 结论

**测试主体是健康的**：约 80 项发现分布在 230 个文件中，其中**真正「全绿但不会失败」**的（第 2/3 类）集中在少数文件，且**没有一项掩盖了当前真实存在的功能缺陷**——即没有「红着却没人知道」的情况，问题方向是**假绿**（绿着但挡不住未来回归）。

按性质分布：

| 性质 | 数量 | 处置 |
|---|---|---|
| **A. 断言恒真 / 无法失败**（假绿，会挡住未来回归） | 15 项 | **本轮已修**（见 §2） |
| **B. 自证 / 同义反复**（断言自己喂进去的字面量） | ~25 项 | 记录；多数只能删除或改为 schema 断言，涉及删用例的判断留待后续 |
| **C. 重复覆盖**（同一边界已有更强用例） | ~20 项 | **本轮不删**——删测试有丢失边界的风险，且收益低于风险；记录在案 |
| **D. 注释/标题腐烂**（不影响通过与否） | ~15 项 | 已修高价值项（见 §2），其余随相关文件下次改动时一并修 |
| **E. 故意保留的 canary** | 7 项 | 非陈旧；`markdown-sanitize.spec.ts` 的 `it.fails` 已核实**仍然必要**（见 §3） |

## 3. `markdown-sanitize.spec.ts` 的 `it.fails`：复核后**仍然必要**
7 个 `it.fails` canary 记录的是 happy-dom 缺陷。本轮做了三项复核：

1. **现状复测**（真探针）：`renderMarkdown` 在 happy-dom 下 `# 标题` → `T`（`<h1>` 被剥）、`<script>alert(1)</script>` → `alert(1)`、`[x](javascript:alert(1))` → `<a href="javascript:alert(1)">x</a>`（**危险协议原样保留**）。canary 的必要性成立，且实际缺口比原记录更大——不止「元素被移除后迭代器死亡」，而是**元素的 `nodeName` 读取失效**。
2. **是否为依赖过期**：happy-dom `20.11.2`（锁定）→ `20.14.3`（当时最新）升级后**输出逐字节相同**，已回滚。不是「升级就能修」。
3. **根因定位**（可作为上游 issue 的最小复现）：happy-dom 在 `Node.prototype` 上自带一个**硬编码返回 `''`** 的 `nodeName` getter（`happy-dom/lib/nodes/node/Node.js`），真正的 getter 在 `Element.prototype`；而 DOMPurify 用 `lookupGetter(Node.prototype, 'nodeName')` 取 getter，`lookupGetter` **遇到第一个自有描述符就返回**，于是永久锁定了那个返回 `''` 的 getter。实测：`lookupGetter` 命中 `Node.prototype` → `""`，而 `Element.prototype` 的 getter → `"H1"`（永远不会被走到）。附带确认不是 DOMPurify 的 `isSupported` 自检问题（该实例 `isSupported === true`）。

**因此**：这 7 个用例在 happy-dom 下**结构性地不可能通过**，`it.fails` 是正确处置而非偷懒；安全判据由 `integration/markdown-xss.spec.ts`（真实 Chromium）承载，2/2 全绿。

**残留风险（记录）**：`it.fails` 会在依赖升级时**反向失效**——happy-dom 若修好该缺陷，canary 会变成「意外通过」并使套件变红。所以**每次升级 happy-dom 必须复跑该文件**（这正是本轮做的动作）。
