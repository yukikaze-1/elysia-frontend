## 1. 系统边界与进程模型

```text
┌─ Renderer（不可信）───────────────────────────────────────────┐
│  Vue 3 + Pinia：表现与 UI 状态                                  │
│  components(58) / stores(22) / live2d(73) / voice / attachments │
└───────────────▲───────────────────────────────┬───────────────┘
                │ window.cyrene（具名窄 API）     │ push: chat:event / tool:event / …
┌───────────────┴───────────────────────────────▼───────────────┐
│  Preload：contextBridge，无 ipcRenderer 直通、无 Node 模块        │
│  每个方法运行时 schema 校验；只暴露具名语义方法                    │
└───────────────▲───────────────────────────────┬───────────────┘
                │ ipcRenderer.invoke(通道)        │
┌───────────────┴───────────────────────────────▼───────────────┐
│  Main：凭据、后端连接、文件系统、工具执行、审计、日志、协议解析      │
│  ipc(89 通道) · transport · tools · attachments · characters    │
│  persistence · diagnostics · credentials · live2d · voice       │
└───────────────┬───────────────────────────────▲───────────────┘
                │ WS v2（帧）+ REST（HTTP）        │
        ┌───────▼───────────────────────────────┴───────┐
        │  外部后端（Python，独立系统，不随前端改名）        │
        └───────────────────────────────────────────────┘
```

**不变式（CLAUDE.md 与 doc 07 的硬约束）：**

- Main 独占秘密与特权操作；Renderer 永远拿不到明文凭据、本地绝对路径、`ipcRenderer`、Node 模块或通用文件/Shell 方法。
- 禁止通用 IPC（`invoke(channel)`／`readFile(path)`／`exec(command)`）。
- 导航、IPC 来源、CSP、自定义协议、路径包含、Electron Fuses 一律 fail-closed。
- 后端工具在客户端**只做展示**；Desktop/本地工具只在 Main 执行，风险**本地重算**，黑名单与非法参数覆盖既有授权。
- Renderer 不接收原始 wire 帧，只消费稳定的前端域事件。
- Live2D 是纯表现，加载失败必须降级且不阻塞聊天。
- 本地绝对路径不得进入 Renderer store 或后端载荷。

**与后端的权力划分：** 后端是外部系统。原始 wire schema 与 REST mapper 全部留在 Main（`src/main/transport/protocol-v2/`）。**本机不存在权威后端仓库副本**，契约事实只能由真实后端（X99 `~/elysia-agent`）或 `check:contract` 门禁产出。

## 3. 关键数据流

| 流 | 路径 | 要点 |
|---|---|---|
| **聊天生成** | WS 帧 → `frame-mapper` → 域事件 → `chat:event` 推送 → `message.store` → 组件 | 一次 generation = 一条 assistant 消息 + 有序 segments；`generation.completed` 是父终止事件；`assistantSegments` 是可见内容唯一真源；token/model/心情保留后端语义与来源标签，**不按字符估算** |
| **附件** | 拖入 → Renderer 只持有 `File` → preload 换 `fileRef` → Main `resolveFileRef` → realpath/黑名单/大小/魔数逐条复核 → 上传 | `UploadFileDescriptor.path` 已在 2026-09-15 从 IPC 面**移除**；`fileRef` 是 32 字节 CSPRNG、TTL 10 min、容量 256；拖入只产生待确认附件，**不自动发送**。**⚠️ 但 doc 07/16 与代码注释声称的「重连即清空」并未接线**（`clear()` 无产品调用点）——见 §7 `S7-C1` |
| **工具与权限** | 后端 `tool.request` → Main 风险重算 → 授权窗 → 用户决策 → 执行 → 审计 + 公开事件 | 风险取「本地基线 ∨ 后端上报」的较大者，黑名单恒 high；按 callId 幂等；终止态不重入；写类工具（带 `content`）恒 high |
| **语音** | ① 普通录音 ② 实时语音会话 ③ 输入法转写 | 三者流程分离；**只有转写 final 文本进草稿**，实时字幕不进；敏感转写文本不进日志与诊断包 |
| **Live2D** | `model-registry` 清单 → Renderer 加载 → 渲染环（rAF / 隐藏窗口下 `beginFrameSubscription`） | 纯表现；加载失败进可诊断失败态，不阻塞聊天；dev 形态经 IPC 供字节（`corsEnabled:false` 下 `cyrene://` 跨源 `fetch` 会被拒） |
| **持久化** | Renderer 防抖 → `chat:persist-session` → Main 原子写 userData 子目录 | 启动水合一次性带回草稿/锚点/会话/消息快照；降级态对用户可见（`CyPersistenceBanner`）；拒绝写入语义与操作级 fail-open 均未变 |

**启动顺序要点**（`src/main/index.ts`）：应用身份/风味（dev 为 `Cyrene-Dev`）→ `setAppDataFlavor` **早于** `requestSingleInstanceLock`（单实例锁派生自 userData 路径）→ userData 子目录守卫（POSIX 走 `O_NOFOLLOW`+fd 锚点，Windows 走 `lstat`+`realpath`）→ 窗口（`window-presentation` 唯一入口）→ 通道装配。

## 4. 契约面

| 面 | 位置 | 门禁 |
|---|---|---|
| IPC 命令通道 | `shared/contracts/ipc.ts` `IpcChannels`（**89**） | `ipc-surface-alignment.spec.ts`：声明面 ⇔ 装配面 ⇔ preload 可达面**集合相等**，三张例外表为空（2026-09-15 实测 89/89/89） |
| IPC 推送通道 | 同文件 `PushChannels`（**8**） | 同上第 5 条：与命令面不相交、不得被注册成 handler |
| 单通道载荷预算 | `main/ipc/channel-budgets.ts` | `ipc-budget-declaration.spec.ts`（新通道必须申报预算） |
| 后端 WS v2 帧 | `main/transport/protocol-v2/raw-schemas.ts` + `frame-mapper.ts` | `pnpm -F @cyrene/desktop check:contract`（对真实后端；WS 36/36 + REST 16/16） |
| 后端 REST | `protocol-v2/rest-schemas.ts` + `rest-mapper.ts`、`character-rest-mapper.ts` | 同上 |
| 前端域事件 | `shared/contracts/events.ts` + `shared/schemas/events.ts` | 单测 + 集成 |
| 线协议夹具 | `src/main/fixtures/wire-v2/*.jsonl` + `.manifest.json` | `refresh-wire-manifests.mjs`；由契约门禁对拍 |

**纪律：** 未知或畸形外部输入必须**显式失败**，不得用 `any`、宽松 schema 或静默丢字段掩盖漂移。新增 IPC 通道必须同时改三处（Main 注册 + preload 引用 + 预算表），否则门禁红。

## 8. 诚实边界清单

以下都是**本快照时点仍然成立**的边界，不应被「阶段 1～7 已完成」的结论掩盖：

1. **本项目仅供本人自用**：第三方资产授权与产物完整性两项阻塞是**按范围解除**，不是已解决。
2. **`test:integration` 整套绿未取得**：偶发红是负载相关，逐项单跑绿；这既是环境事实，也意味着**全量集成不是可靠门禁**。
3. **`lil` 模型不在 git**：CI 上 Live2D 的 lil 分支仍然不执行（修掉的是「静默」，不是「CI 覆盖」）。
4. **`fileRef` 的 `bytes` 分支仍可直接调用**：任何字节都可以 POST 给已连接后端，**未主张消除**。文件数上限（每批 10）是真实执行的，但**每 kind 与聚合的大小上限按对端自报 `size` 判定**，`byteLength` 从不校验——即体量约束只对诚实客户端成立（见 `S4`）。真实文件的 `fileRef` 路径也**没有集成覆盖**（夹具只能造合成 `File`，落进 `bytes` 分支），只有 preload 单测覆盖。
5. **S5-B2 的三处文档过度声称仍未处置**（「重连即清空」不存在、`bytes` 上限口径、存在性 oracle）——见 §7.2b 与汇总 §2.1；在处置前，doc 07 §9.2 的相关句子**不可作为当前事实引用**。
6. **`windows-runtime` 跑不出运行时信号**：这是 runner 形态（Session 0、无交互桌面）的结构性结论，不是「还没稳定」。
7. **门禁覆盖不到的地方**：`docs/` 非编号文档、`ui/`、`docs/archive/**` 与 `docs/review/**` 的链接、以及所有「断言在实现坏掉时不会红」的测试（含 `window-presentation-guard` 正则可绕过的那些写法）。
8. **本机无权威后端副本**：契约事实只能来自真实后端或 `check:contract`；本机若出现后端目录副本，**不可作为权威来源**。
