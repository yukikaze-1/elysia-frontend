# H-11b renderer 半边 —— 持久化降级对用户可见（决策记录）

**日期：** 2026-09-13
**范围：** doc 16 §5 第 7 条（H-11b 的 renderer 半边）；评审 [2026-09-11 全量评审](2026-09-11-full-frontend-review.md) P0-3 行末的「**会引入『持久化降级』这一新运行态，UI 需有承载**（可先只记日志 + 拒绝写入，不新增 UI）」；doc 06 §12「缓存损坏时：隔离损坏文件 → 使用默认状态启动 → 从后端恢复 → **提示用户**可导出诊断信息」
**触发：** 用户 2026-09-13 从「还剩什么」清单中选定三批，本记录是其中的 ⑤
**结论：** **已落地**。持久化降级/写失败第一次有了**用户可见出口**（全局横幅），且向 Renderer 暴露的信息**不含任何本地路径**。

## 1. 修之前到底是什么状态（全部实测，不是转述评审）

主进程侧的 H-11b 在 2026-09-11 已修完并有单测证据（`session-store.spec.ts`「原文件逐字节未变」）：隔离失败 → 置降级位 → `assertWritable` 拒绝一切写入。**缺的是"告诉用户"这一半**，实测三条独立事实：

| # | 事实 | 实测方式 |
|---|---|---|
| 1 | 拒绝写入抛的是**泛化码** `UNKNOWN` | `assertWritable()` 原文 `new CyreneError(CyreneErrorCode.UNKNOWN, …)`；经 `createIpcHandler` 的兜底分支后 Renderer 只会收到 `内部错误`。本轮变异 M2 打出了修复前的原样报文：`[UNKNOWN] 持久化已降级（drafts-v1.json：read-failed:unknown），已拒绝写入以保留现场` |
| 2 | Renderer 侧**无条件 fail-open 吞掉** | `draft.store.persistNow` 的 catch 是 `catch { return undefined }`，注释写着「fail-open（C1 同款）：持久化失败保内存态，下次触发重试」——对单次抖动是对的，对**本进程内不会自愈的降级态**则等于永久沉默 |
| 3 | `getLastError()` **只有测试在读** | 全仓 grep：`sessionStore.getLastError()` 的调用点只有 `session-store.spec.ts`；没有任何 IPC 通道、没有诊断页出口 |

**用户可见症状**：草稿照常出现在输入框、界面一切正常，重启后全部消失。而且 doc 06 §12 早就写了「**提示用户**」这一步——这是一条**规格已要求、实现里从未存在**的条款，与 2026-09-13 已收口的规格漂移台账同类。

## 2. 设计决定（含取舍）

### 2.1 拆两个错误码，而不是复用 `UNKNOWN`

新增 `PERSISTENCE_DEGRADED`（降级：本进程内不会自愈）与 `PERSISTENCE_WRITE_FAILED`（单次写失败：磁盘满/权限/只读目录）。理由不是命名洁癖，而是**用户该做的事不同**：降级态是「**故意**不写以保现场」，重启不会好，用户需要先处置那个文件；单次失败则是「这次没写成」，恢复可写后下一次键入会自动重试。两类混在一个码里，UI 只能给一句无用的泛化提示——那正是 M-19 的形态。

`toWriteFailure()` 只采纳 **errno 形状**的 code（`/^[A-Z0-9_]{1,32}$/`），并把消息拼成 `本地保存失败（ENOSPC）`；非该形状一律退化为 `本地保存失败`。已有语义码（`DRAFT_LIMIT_EXCEEDED`／`IPC_MESSAGE_TOO_LARGE`／`PERSISTENCE_DEGRADED`）**不覆盖**。

### 2.2 投影必须无路径：内部字段分栏，而不是"记得别传"

原先 `degraded` 只有一个字符串 `reason`，其值是 `` `${trigger}; isolate-failed:${detail}` ``——其中 `detail` 是 **fs 错误原文**，实测含绝对路径（例如 `isolate 目标逃逸安全根: /abs/path/drafts-v1.json`）。直接把它发给 Renderer 就违反了架构不变量「Renderer 永远拿不到绝对本地路径」。

修法是**在数据结构上分栏**，而不是靠调用方自觉：

- `degraded = { file, trigger, detail }`；
- `getLastError()` 保持原样（`trigger; isolate-failed:detail`，**含路径**）→ 诊断、日志、既有测试语义逐字不变；
- 新增 `getDegradedNotice()` → `{ file, reason: trigger }`，**去掉 detail**，`trigger` 本身来自封闭取值（`read-failed:<errno>` / `not-an-object` / `schema-version-mismatch:<n>`），天然无路径。

两个方法同源同字段，不存在"两处各自漂移"的风险。集成用例把这条钉成了断言：投影序列化后不得出现临时根路径、盘符、`/tmp/`、`/home/`。

### 2.3 随水合一次性告知，而不是等下一次键入被拒

`hydrate()` 现在带 `persistenceDegraded`（仅在降级时出现）。这是用户进入应用后**第一个**能知道「本地保存已停用」的时刻——降级发生在 `load()`（启动早期），而写入被拒要等到用户下一次键入并越过 800ms 防抖。变异 M4（让 `draft.store.hydrate` 忽略该字段）实测：横幅在断言时刻 count=0，**证明这条路径是必要的**，不是"顺手加的字段"。

字段纳入 `stateBytes()` 预算（+256B），并**不能**被 4MiB 体积降级丢掉——它正是"保存已经不可用"的告知，丢了就等于又静默一次。

### 2.4 横幅挂全局，不挂聊天区

`SessionStore` 管的是**两个文件**：`drafts-v1.json`（草稿/锚点/lastActive）与 `message-cache-v1.json`（会话列表+消息快照）。挂在聊天区意味着"切到设置页就看不见了"。故与 `CyRendererCrashBanner` 同款挂在 `App.vue` 根部，集成用例显式断言**切到设置页（chat 视图被 v-else 卸载）后横幅仍在**。

### 2.5 文案归 UI 层，store 只产出码

沿用 2026-09-10「多套 UI 基础」的既定分工：`draft.store` 只产出 `{ code, file?, reason? }`，措辞一律经 `error-message.ts` 的单一映射表。两条新码的文案是动作导向的（降级 → 「为避免覆盖现场已停止一切写入」；写失败 → 「草稿与离线缓存没有被写入磁盘」），横幅再补一句**不同的**动作建议（降级 → 先备份该文件再重启；写失败 → 恢复磁盘可写后会自动重试）。

### 2.6 不改变拒绝语义，也不改变操作级 fail-open

写入**仍然失败**（fail-closed 不变）：横幅不是"失败了也说成功"的遮羞布。而聊天/连接/删除等**操作**继续 fail-open（`chat-service.ts:92/105/112` 三处 `.catch(() => {})` 原本就在，本批未动）——即降级态下应用照常可用，只是不落盘，并且**用户知道**。

## 3. 刻意没做（逐条给理由，不藏在提交信息里）

| 未做项 | 理由 |
|---|---|
| **M-19**：设置保存失败仍不可见（`settings.store.saveError` 全仓无组件渲染） | 这是评审里的**另一条独立缺陷**，不在本批范围；且它牵出 doc 11 §9「未同步/同步中/已同步/错误」四态，台账里对该行的建议是「建议砍或**改写规格**」——属产品决定，不能由实现顺手替他定了 |
| `cache-messages` 通道的**单次**写失败接到 UI | 该通道在 `cache.store.pushMessages` 里 `catch { /* 缓存缺落由后端调和兜底 */ }`，是刻意的 fire-and-forget。**但降级态本身是覆盖它两个文件的**（`getDegradedNotice()` 报的是触发降级的那个文件，可能是 `message-cache-v1.json`）。记为残余，不在本批 |
| 横幅上加「重试」按钮 | 下一次键入/切会话本来就会重试；加按钮等于把"自动重试"变成用户负担 |
| 把 fs 原文（`detail`）显示给用户 | 违反路径边界；且 fs 原文对用户无行动价值，errno 码已在 message 里 |
| 横幅里加「导出诊断」入口 | doc 06 §12 的「提示用户可导出诊断信息」由既有诊断页承担；本批的告知重点是"别关窗、先备份"，加第二个入口反而稀释 |

## 4. 验证

### 4.1 新增/扩展的用例

| 层 | 文件 | 钉住什么 |
|---|---|---|
| 单测（主进程） | `tests/unit/session-store.spec.ts`（+4 条） | 拒绝写入 = `PERSISTENCE_DEGRADED`；降级态随 hydrate 出且**投影无路径**（同时断言 `getLastError()` 仍含路径——两边不混淆）；健康时不带该字段；真实写失败（父目录消失）= `PERSISTENCE_WRITE_FAILED` 且 message 无路径分隔符；`toWriteFailure` 纯函数直测（errno 形状才采纳、语义码不覆盖） |
| 单测（Renderer） | `tests/unit/draft.store.spec.ts`（+5 条） | 被拒 → 置位且**内存态仍保留**；单次失败 → 置位、下次成功写回即清除；降级态**不被一次"成功"响应清掉**；水合即显示；健康水合清除 |
| 单测（组件） | `tests/unit/cy-persistence-banner.spec.ts`（5 条） | 无故障不渲染；`role="alert"`；两类故障的动作建议必须不同；未映射的 IPC 码也有兜底句（不留空白）；不回显路径 |
| 集成 | `tests/integration/persistence-degraded.spec.ts`（2 条） | 见 4.2 |

### 4.2 集成用例怎么造出"真实降级"（本轮最费劲的一处，值得记下）

要验证"降级能到达用户"，必须让 Main **真实进入降级态**，而唯一的真实入口是「损坏文件隔离失败」。不能用 ACL/权限（Windows 上不可移植），于是用**符号链接**：`app-cache/drafts-v1.json` 预置成指向 userData 之外的链接 → `openSafeFile` 拒符号链接（posix `O_NOFOLLOW` / windows pre-open `lstat`）→ `readFile` 进隔离分支 → `isolate()` 的 `assertContained` 因 realpath 越根而上抛 → 置降级位。**全程是产品代码，测试没有注入任何专用分支**。

**平台发现**：本机（Windows，未开开发者模式）`symlinkSync` 建**文件** symlink 直接 `EPERM`，第一版用例因此**整组被跳过**——也就是说它只会在 CI（Linux）上跑，本机拿不到任何端到端证据。探针实测后改用 **目录 junction**：Windows 上**免特权**可用，且 `lstat().isSymbolicLink() === true`、`realpath` 解析到外部 ⇒ **触发与文件 symlink 完全相同的降级路径**（两种形态实测 `trigger` 都是 `read-failed:unknown`）。

故用例按可用形态择一（探测方式与本仓 `protocol-handler`／`safe-open`／`live2d-registry`／`tool-executors` 同款：真建一次链接，失败即认为不可用）：
- **file-symlink**（Linux）：最强断言——**外部目标文件逐字节未变**；
- **dir-junction**（Windows）：断言改为"外部目录里除哨兵文件外什么都没多出来、哨兵内容未变"（此时被覆写的对象是链接本身而非某个文件）；
- 两者都不可用 → 整组跳过并在测试名里写明，**不伪装通过**。

**两种形态都拿到了真实证据**（缺一不可，否则等于只有一半平台验过）：
- 本机 Windows（探测结果为 `dir-junction`）：2/2 通过；
- CI Linux（探测结果为 `file-symlink`）：run `34743246107` 的 **shard 3/3** 日志 `✓ tests/integration/persistence-degraded.spec.ts (2 tests) 6124ms`——即**更强的那条断言（外部目标文件逐字节未变）在真实 Chromium + 真实 Main 上成立**。

`reason` 的断言用**封闭词表正则**而非字面值：具体标签取决于 fs 错误是否带 errno（posix 的 ELOOP 与 windows 的 lstat 拒绝都会在 `safe-open` 内被包成无 errno 的 `SafeOpenError`，两边实测都是 `read-failed:unknown`），但用例要钉的是「封闭词表 + 无路径」，写死具体值会把平台差异变成假红。

### 4.3 阳性对照（防止"外部未变"变成假绿）

"键入后外部文件未变"在**键入根本没触发写入**时同样成立——那是假绿。故同一文件里加了一条**常驻**（不受 symlink 守卫影响）的阳性对照：健康应用里走**同一条键入路径**，证明「键入 → 800ms 防抖 → 真的写了盘」成立，同时断言此时**不显示**横幅。

### 4.4 变异验证（4 次，每次确认"变异真的改了代码路径"）

| 变异 | 预期红点 | 实测 |
|---|---|---|

| M2 `assertWritable` 的码改回 `UNKNOWN` | 集成 ③′ 专属码断言 | **红**，且打出修复前原样报文 `[UNKNOWN] 持久化已降级（…）` |
