# EXT-01：使用范围限定为个人自用 ⇒ 解除对外分发阻塞

**记录日期：** 2026-09-12

**文档状态：** 生效中

**决策类型：** 使用范围决策 / 阻塞项解除（supersede 范围部分）

**影响范围：** doc 16 §4 阻塞项与整改计划的 P0-7；doc 12 §4.7 G-01；doc 09 的发布矩阵（引用关系，不改其设计）

**证据来源：** 用户 2026-09-12 的明确陈述（见 §2）；[2026-09-10 第三方资产授权与来源立为阻塞项决策记录](2026-09-10-第三方资产授权与来源立为阻塞项-决策记录.md)（本记录**不改写**它的事实与结论，只改变其约束面的适用性）

---

## 1. 背景

2026-09-10 的记录把「第三方资产授权与来源」立为显式阻塞项 `EXT-01`，并明确其约束面是**任何对外分发的产物**：

> `EXT-01` 的约束面是「任何对外分发的产物」，不局限于阶段 8……**当前可接受的用途**：内部/个人开发验证与本机 userData 装配。**不可接受**：把含 SDK 的产物交付给第三方，或在公开渠道分发。

该记录同时列出了 6 条解除条件（EULA 正文入仓、Release License 适用性结论、8 个示例模型逐模型承诺、3 个第三方模型作者授权、AI-Chatbot 分类答复留档、覆盖 vendor 的许可门禁）。这 6 条**至今一条都未完成**，因此在报告与本项目文档里一直被计为「发布阻塞」。

## 2. 用户决策（2026-09-12）

用户就本项目的使用范围与 SDK 授权作出如下陈述：

1. **本项目仅供本人自用**；
2. **所用 Cubism SDK 为个人授权**；
3. 所谓「发布」**就是本人自己安装使用**，不存在交付给第三方的场景。

## 3. 决策

1. **`EXT-01` 不再构成本项目的阻塞项。** 理由不是"授权问题已解决"，而是**其约束面没有实例**：该阻塞的判定对象是"对外分发的产物"，而本项目不存在对外分发。约束面为空 ⇒ 阻塞不成立。
2. **整改计划中的 `P0-7（发布阻塞项收口）` 随之解除**（doc 16 §4 与报告第 1 步）。它原本只依赖 `EXT-01`，现无待办。
3. **使用范围作为前提记录在案**（取代 2026-09-10 记录 §3.4 的用途判定）：可接受 = 本人自用（含本机打包安装）；不可接受 = 交付第三方或公开渠道分发——**一旦出现后者，本记录立即失效**，`EXT-01` 连同 2026-09-10 记录列出的 6 条解除条件**原样恢复**，无需重新论证。
4. **不做「已合规」的结论。** 本记录只声明范围，不断言许可已满足（见 §4）。

## 4. 本记录明确不做的事情

- **不做法律结论，也不主张合规。** 2026-09-10 记录 §2 的实测事实**全部继续成立且未被推翻**：仓库内仍无四份 EULA 正文、无 Release License 适用性结论、无逐模型承诺记录、`lil` 模型的来源仍是一个 gitignored 的本地临时目录、vendor 三树仍被机密扫描整树排除且无替代检查。本记录一个字都没有改变这些事实；它只说明**在本项目的使用范围下，这些事实不再构成阻塞**。
- **不改写 2026-09-10 的记录。** 那份记录的历史结论原样保留（本项目纪律：历史记录以新记录取代，不重写其历史主张）。
- **不修改 doc 09 的发布设计**，也不动阶段 8 的既定决策。
- **不因此删除任何既有材料或门禁**；不以本记录为由放宽任何现有检查。

## 5. 失效条件（触发即恢复阻塞）

出现下列任一情形时，本记录立即失效，`EXT-01` 恢复为阻塞项：

1. 产物被交付给第三方（含试用、客户交付、代安装）；
2. 在公开渠道分发（含公开仓库 Release、安装包外链）；
3. 使用范围由"本人自用"变为任何多人/组织使用；
4. SDK 授权由个人授权变为其它类型且适用性未经确认。
