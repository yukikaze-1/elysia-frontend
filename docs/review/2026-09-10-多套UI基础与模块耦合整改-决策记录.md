# 多套 UI 基础与模块耦合整改（2026-09-10）

**记录日期：** 2026-09-10

**文档状态：** 生效中

**整改动机：** 产品方向明确「将来 UI 风格可能有多套，但功能不应依赖 UI」。为此先做了一次模块耦合与内聚实测审计，结论是**方向对、但只做到一半**：进程边界与颜色体系已经很好，而功能层里嵌着界面文案、HTML 模板与 DOM 引用。本记录是审计结论、整改内容与验证证据。

**审计口径：** 以「依赖方向」为唯一判据，不按目录分层的好看程度评价。

## 2. 整改内容

### 2.1 代码块 HTML 生成外移到组件（破口 1）

**前置核实**：`utils/markdown.ts` 同时承担**安全消毒**与**HTML 拼装**。消毒是安全边界（CSP 第二道防线），**不可外移**。

**处置**：消毒管线逐字不动（仍是 `marked.parse → DOMPurify.sanitize`），只把「消毒**之后**的包裹」从拼字符串改为按 `<pre><code>` 边界切成结构化数据：

```
MarkdownBlock = { kind:'html', html } | { kind:'code', language, content }
```

- `utils/markdown.ts`：新增 `splitCodeBlocks`（纯数据切分）+ 实体还原（`&lt;`→`<`）；删除 `wrapCodeBlocks`（功能层拼 HTML）。
- 新增 `components/CyCodeBlock.vue`：结构、文案（`复制`/`已复制`/`代码`）、样式、复制交互全部归 UI 层。
- `CyMarkdown.vue`：HTML 块走 `v-html`，代码块走组件。

**安全语义不变**：代码正文改用**插值**渲染（`textContent` 语义），含 `<script>` 的代码只作为文本显示——比原先 `v-html` 更严。语言标识经 `/^[A-Za-z0-9_+-]{1,32}$/` 过滤后才可用于展示，防注入。

**顺带修正**：切分按 `<pre><code>` 文本边界，不要求块级位置，故**嵌套在列表/引用内的代码块同样被切出**（此前 `wrapCodeBlocks` 也是全局正则，行为一致）。

### 2.2 会话边界事件取代 store 直接控制渲染缓存（破口 2）

**处置**：新增 `utils/session-boundary.ts`——功能层只播报「发生了会话边界」这一领域事实，谁需要清理谁订阅。

- `message.store.resetConversation` 改为 `emitSessionBoundary(...)`，不再 import 任何 UI 模块。
- `utils/markdown.ts` 在**模块加载时**订阅并清空自己的缓存，不依赖任何组件是否挂载。

**为什么订阅在模块加载而非组件挂载**：只要 markdown 渲染能力存在（模块被加载），会话切换必清空——安全语义（M-2 防敏感内容跨会话驻留）不因组件生命周期出现窗口期。

### 2.3 token 契约立为门禁（破口 4）

- `tokens.css` 补齐 5 个缺失 token（含亮/暗双值）。
- 组件侧移除全部 `var(--cy-x, <硬编码>)` 兜底，以及 `var(--cy-danger, #d33)` 一类内联兜底。
- 新增 `tests/unit/token-contract.spec.ts`，三条契约：① 组件引用的任何 `--cy-*` 必须已定义；② 组件不得自带 `--cy-*` 定义；③ 组件不得为 token 引用提供兜底值。

### 2.4 几何 token（破口 6）

实测频次后发现间距**不是阶梯而是 1–20px 密集带**（5/7/9/11/13 各 20 处以上），按偶数档只能覆盖 59.5%。故采用「基准单位 2px，`-N`=2N px，`-N-5`=2N+1 px」的档名规则：

- 间距 16 个（`--cy-space-0-5`=1px … `--cy-space-9`=18px）
- 圆角 9 个（`--cy-radius-3`=6px … `--cy-radius-pill`=999px、`--cy-radius-circle`=50%）
- 字号 5 个（`--cy-font-xs`=10px … `--cy-font-xl`=15px；14px 复用既有 `--cy-font-base`，不改其语义）
- 动效 2 个（`--cy-motion-fast`=150ms、`--cy-motion-base`=180ms）

**规模**：54 个文件、1045 条声明、1239 个值（占 1278 个值的 **96.9%**）。保留 39 个低频值不造档位（出现 <10 处），以及 `margin: 0` 一类复位量与 `animation` 时长（元素自身节奏，非皮肤语义）。

**等价性证据**：把改写后的 `var(--cy-*)` **反解回字面量**与改动前快照逐字节比对，54/54 一致；57 个 `.vue` 去掉 `<style>` 后逐字节比对，57/57 一致（模板/脚本/选择器一行未动）。

### 2.5 解 store 循环依赖（破口 5）

**根因分析**：环的唯一成因是「非会话模块也要读当前会话信息」。把 `currentId` 放在 `conversation.store` 就等于让它成为全应用中枢，任何读取者都会与它成环。

**处置**：新增 `stores/session.ts`——会话身份的**最小公共下沉**（零 store 依赖，故任何模块依赖它都不成环）：

- `currentId` / `activeCharacter`（角色绑定）/ 会话列表只读镜像
- 写方唯一：`conversation.store` 经 `watch(..., { immediate, flush:'sync' })` 单点镜像
- 读方：`message.store`（`currentConversationIdRef` + `findConversation`）、`settings.store`、`voice.store`

**为什么镜像而非逐点改调用**：`currentId` 有 7 个赋值点（activate/create/remove/离线水合/onConnected…），逐点插同步调用迟早漏改；`watch` 保证「只要有写入就同步」，是新写入路径的天然兜底。

**结果**：Tarjan SCC 由 1 个 4 节点环变为 **0 环**。新增 `tests/unit/store-graph.spec.ts` 立为门禁。

### 2.6 功能层脱离 UI 状态与 DOM（破口 7）

**可见性**：`live2d.store` 不再读 `layout.store`。改为 UI 告知——`CyLive2DPanel` 自行组合可见条件（视图/布局折叠/窄窗属 UI 决策）后调 `store.setSurfaceVisible(v)`。

**TTS 宿主元素**：`live2d.store` 不再读 `voice.store.ttsAudioEl`。改为 UI 告知——`CyTtsPlayer` 调 `store.setTtsAudioElement(el)`。同时 `voice.store` 的该字段由响应式 `ref<HTMLAudioElement>` 改为**普通变量 + 存取器**（原先对 DOM 节点建 Vue 深代理，既是性能负担也无意义）。

**为何通知必须来自 UI**：`voice.store → live2d.store` 会造出新的环；UI 是唯一同时看得见两者的层。这与 `setSurfaceVisible` 同向，形成一致约定：**UI 知道自己的 DOM 与布局，功能层只消费**。

### 2.7 错误文案映射（破口 3）

新增 `utils/error-message.ts` 作为「错误码 → 用户可读文案」的**单一来源**，回退链顺序即正确性的一部分：

1. `backendCode` 映射（通用包装码 `BACKEND_REJECTED` 之下的具体后端原因更精确）
2. `code` 映射
3. **来自 Main 的已公开错误原文**（跨进程错误没有本地映射，丢弃会变成空白）
4. 调用方兜底句（描述操作语境）

- 11 个 store 的 46 条中文文案改为诊断标识 `'LOCAL:<CODE>'`（本地错误无后端原文可用，需占位以保证回退链 ③ 不误触发）。
- `character-error.ts` 退化为 `errorMessage` 的语义别名（保留调用点与测试），消除两张映射表漂移。
- UI 层 15 处渲染点接入映射器。

**刻意不收录 `BACKEND_REJECTED` / `UNKNOWN`**：给它们编泛化文案会**盖住**后端说明——这是实测到的真实回归（把「后端返回的可公开说明」改写成了「后端拒绝了本次操作。」）。

### 2.8 三项新门禁

| 门禁 | 文件 | 抓什么 |
|---|---|---|
| token 契约 | `tests/unit/token-contract.spec.ts` | 引用落空 / 组件私自定义 token / token 兜底值 |
| store 无环 | `tests/unit/store-graph.spec.ts` | store 间循环依赖（Tarjan SCC） |
| 文案映射 | `tests/unit/error-message.spec.ts` | 回退链顺序 + 全部本地码都有映射（防诊断标识外泄） |

**两处门禁实现上的坑（已修，记录以免重犯）**：

- **注释会造假边**：`store-graph` 起初把一条解释性注释里的 `from './conversation.store'` 当成真实依赖，凭空报出一个并不存在的环。现已先剥注释再取边。
- **扫描正则吞值**：`[^;}]+` 形式会把 `.a:hover { padding: 8px; }` 的 `padding` 当成 `a: hover { padding…` 的值吞掉，必须用 `[^;{}]+`。几何审计因此重跑。

### 3.3 一处测试基础设施修正

`CyTtsPlayer` 为口型接线引入 `live2d.store` 后，`cy-conversation-list.spec.ts` 立即以 **0 test** 崩溃（`ReferenceError: Live2DCubismCore is not defined`）——即「测试能否跑起来取决于间接依赖顺序」。

根因：vendored Framework 的 `cubismmodel.ts` 在**模块作用域**访问全局 `Live2DCubismCore`（真实运行时由 renderer 的 `live2dcubismcore.min.js` `<script>` 提供）。此前该桩只写在 `live2d.spec.ts` 内。

**处置**：提升为全局 setup（`tests/unit/setup/live2dcubismcore.ts` + `vitest.config.mts` 的 `setupFiles`），使单测环境与生产环境一致（Core 恒在），import 链变化不再影响可测性。

## 4. 刻意未做（附理由）

| 项 | 理由 |
|---|---|
| **拆分 `message.store`（46 actions）/ `character-editor.store`（45 actions）** | 这是**内聚**问题，不是 UI 隔离问题——本次目标（换 UI 不动功能）已达成。而这两个文件是本仓风险最高、测试覆盖最密的模块，纯为行数拆分收益与回归风险不成比例，且会显著扩大 diff、淹没本次的架构改动。留作后续独立批次。 |
| **组件 `:style` 内联样式（11 处）** | 多为数据驱动的头像底色（`themeColor`）与运行时注入的 `--cy-public-mood-intensity`，属数据而非皮肤决策。 |
| **`border` 宽度 / `box-shadow` / `transform` 位移 / `line-height`** | 仍为硬编码几何。若要做「结构维度完全换肤」，下一轮应收 border 宽度与阴影。当前已覆盖 96.9% 的指定性质。 |
| **错误**映射**未覆盖的渲染点（约 4 处） | `CyToolCard` 的 `record.error?.message` 是后端工具执行结果原文（非 `PublicError`），不属同一映射面。 |
| **`useLayoutStore().viewportWidth = 2000` 等测试辅助** | 测试内布局预设，与生产耦合无关。 |

## 5. 残余风险

1. **`session.ts` 镜像的时序依赖**：`conversation.store` 是唯一写方，读方若在其创建前读取会得到 `undefined`（与改动前同样依赖初始化顺序，未变差）。`session.ts` 零 store 依赖保证了不会成环，但**不保证初始化顺序**——若将来出现「读方先于 conversation store 创建」的真实竞态，需改为显式初始化屏障。
2. **`splitCodeBlocks` 是文本边界切分**：不解析 HTML 树。若 DOMPurify 输出形态变化（如 `<pre>` 属性顺序改变），正则仍匹配（只依赖 `<pre><code …>` 标签本身），但**若将来把 `pre` 移出 `ALLOWED_TAGS`，代码块会整体退化为 HTML 块**——`token-contract` 不覆盖此事，`markdown-sanitize.spec` 的配置钉住用例会红。
3. **`--cy-space-4-5` 这类档名需要记住「单位 2px」规则**：可读性代价已在 `tokens.css` 顶部注明。若更偏好「名字 = px 值」，改名是纯机械替换。
4. **几何 token 未覆盖 `animation` 时长**：旋转/呼吸类动画按元素自身节奏保留硬编码，换肤不会统一改变它们。
