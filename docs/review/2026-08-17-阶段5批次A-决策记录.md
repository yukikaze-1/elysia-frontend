## 4. 关键决策 rationale（本批实现语义）

- **两级可用性（D5A-07）**：`available` 门禁只锚定 integrity 清单覆盖的模型文件（装配产物全量覆盖），`preview.png` 条目豁免（缺失/尺寸不符不置可用性为假，UI 缺 preview 用占位）；`available` 语义与「列表」语义解耦——非法目录根本不列出，合法但文件损坏的列出且不可用。
- **fail-closed 供给（D5A-08）**：首个命中某模型的请求 `await verifyIntegrity`（同模型共享同一 pending promise），失败 → 熔断该模型 + 4xx；防「校验前已服务被篡改文件」。路由不做逐请求 hash——`verifyIntegrity` 带 verified/failed 短路（R-3，会话内每模型一次）。
- **settings 契约向后兼容（D5A-10）**：`SettingsStateSchema` 对 `live2d` 用 `.default(DEFAULT_LIVE2D)`（`{enabled:true, modelId:null}`）——input 可缺省，旧 `settings.json` 无 `live2d` 段也能通过 parse；**不得**做成必填，否则老文件走 corrupt+全量重置清掉 voice/dictation；`SettingsService.save()` 增第三 merge 行（防部分 patch 丢兄弟子树）；`SettingsPatchSchema` 增嵌套 `live2d` partial（否则 `{live2d}` patch 被 zod 剥掉成死代码）。
- **大纹理处理（D5A-11 + R-6）**：lil 8192 纹理超 SwiftShader `MAX_TEXTURE_SIZE` → `Live2DTextureError` → 优雅失败 → 静态头像回退，不 crash；CI 用 Haru 2048 与 wanko（确定性切换目标），修女莉尔仅本机装配 skip-when-absent。
- **buildFitMvp 平移项方向修正（Task 5 P1）**：真实 Haru.moc3 顶点居中取证——原 `m[12]=-1/m[13]=-0.75` 把模型推至 NDC 左下角外（约 92% 裁出屏，不影响「canvas 非空像素」验收但砸首帧视觉）→ 移除角原点平移（`m[12]=m[13]=0`，居中空间 scale-only）+ 矩阵不变式单测。
- **CLI/Electron appData 恒等（R-6 bound）**：装配工具 `resolveModelsDir(env)` 镜像 Main `expectedUserDataBase()` 平台公式（Linux `XDG_CONFIG_HOME??$HOME/.config` / Windows `%APPDATA%` / macOS `~/Library/Application Support`），配多平台 env 单测 + Electron 集成用例 9 用真实 `app.getPath('appData')` 对比（防装配路径漂移）。
