## 3. 本批设计决策（D-A3~D-A14）

| # | 事项 | 定案 | 理由 |
|---|---|---|---|
| D-A3 | `ModelProfile` 粒度与 id | **「可激活模型」级展开**：内置 provider 每个 model 一条，`id = "<provider>/<model>"`（如 `deepseek/deepseek-v4-flash`）；custom 条目一条，`id = "custom/<name>"`；无自定义合成键 | `ModelProfile.id` 直接作为后端 `switch_model{model}` 可接受的标识；custom 条目后端 `resolve_model_params` 只解析 `custom/<name>` 两段，`models` 列表仅展示不参与激活标识——内置与 custom 不对称性由后端语义决定，前端归一化如实保留 |
| D-A4 | `credentialStatus` 取值 | **两态实际产出**：`configured` / `missing`（由 `credentialConfigured` 映射）；`expired` 枚举保留但 P4-A 无来源产出 | 后端 `credentialConfigured` 只读布尔，无 expired 来源；保留枚举避免未来扩展破坏类型 |
| D-A5 | 当前激活来源 | `server_info.services.{llm,stt,tts}.model` 握手归一化 + `switch_model_result`/`set_tts_voice_result` 更新；**无 `model.profile.changed` wire 事件**（后端 `556117a` grep 证实不存在，doc 02 §19 事件表属领域意图） | 不等待/不消费不存在的 wire 事件；激活状态由握手快照 + 本端 result 帧回显维护，失败不乐观更新 |
| D-A6 | 凭据提交语义 | **一次性提交**：`apiKey` 只存在于表单组件、绝不写入 store 草稿/IPC 出参/日志；提交成功或失败后立即清空；编辑 custom **不回显已存密钥**，仅显示 credentialStatus 与「留空则保持原密钥」提示 | 后端 save 响应已剔除 `api_key`（`_strip_secret_keys`）；Renderer 永不持有可能回显密钥的明文路径 |
| D-A7 | 模型连接测试 level | **对齐后端两值**：`level: 'connectivity' \| 'usable'`（`POST /api/providers/test`） | 后端只接受这两值；类型化测试在 UI 分为「测试连接 / 可用性测试」两个入口 |
| D-A8 | 切换语义 | **切换只影响新请求**，不破坏当前生成/转写/播放 | doc 12 阶段 4 验收门槛原文；`switch_model` 语义即「新请求生效」 |
| D-A10 | 设置持久化 | **P4-A 不建 settingsStore / 设置持久化基础设施**；设置中心「当前页」不记忆（打开即回「模型服务」） | 本批模型服务设置全部是后端状态（providers/switch_model/tts_voice），无本地持久化需求；D3 自动朗读开关等本地设置随 P4-B/阶段 5 引入 |
| D-A11 | TTS 试听传输 | **一次性 media 路由**：Main 收到 `TtsPreviewResult` 后把 `audio_base64` 解码为字节，存入一次性内存缓存并扩展媒体路由为 `tts-preview`（复用 `MEDIA_PATH_PREFIX`/`parseMediaPath`），返回 `cyrene://renderer/__cyrene-media/tts-preview/{id}`；缓存 60s TTL 定时清理，未知 id → 404 | 试听二进制/URL 不落 Renderer store；与现有 attachment 媒体代理编排一致；试听是独立操作，不打断当前回复生成 |
| D-A14 | WS result 帧关联 | **单服务单 in-flight**：store 每个 service（llm/stt/tts）与 `set_tts_voice` 各自最多一个在途命令；`switch_model_result` 按回显 `service`+`model`、`set_tts_voice_result` 按回显 `voice` 匹配 pending 才更新；不匹配（迟到/乱序/其他客户端切换）→ 忽略更新并记录该 service 需下次 `GET /api/providers`/`listTtsVoices` 重新校准；超时 10s reject | 两 result 帧均不带 `clientRequestId`；不引入重放队列（本批不超前实现）；同一帧同时带 `ok:true` 与 `error` 不会发生 |

## 6. DataCloneError 集成 bug 修复记录（P4-B 确认）

Task 10 集成测试（真实 Electron + mock 装配）暴露 Task 8 store 的**真实联调级 bug**：

- **现象**：向导「测试并保存 / 保存并设为当前」失败，wizard 内错误为 `An object could not be cloned.`。
- **根因**：`saveProfile` 内 `{ ...draft }` 展开的 draft 来自 reactive 容器 `drafts.value[key]`，其 `models`/`capabilities` 是 **reactive 数组 Proxy**；经 `contextBridge → ipcRenderer.invoke` structured-clone 抛 `DataCloneError`。Task 8 单测不经 contextBridge，未覆盖。
- **修复**：`saveProfile` 显式构造纯对象 `UpsertModelProfileCommand`（数组克隆为普通数组），行为对纯对象输入不变。commit `3e0588a`。
- **确认要求（P4-B）**：真实后端装配下同一 store 路径同样受益（同一 `saveProfile`），建议 P4-B 复盘时确认 real 后端装配无同类代理克隆问题。
