## 1. 结论

第二轮 Windows Electron + 真实后端联调已经证明多角色主要产品路径可用。前端本轮**没有发现需要立即修改协议、领域模型或 UI 主流程的 P0 产品缺陷**；现有连接世代保护、会话后端确认后提交、角色身份栅栏和迟到帧隔离均应保留。

Stage H 尚不能正式闭账，原因不是前端主流程未实现，而是：

1. 后端官方 pinned/follow_latest 夹具会生成公开契约无法序列化的数据；
2. 后端官方清理命令在角色更新到 revision 2 后会留下孤儿 revision；
3. “A 的 tail 仍在执行时切到 B”与当前公共 API 的 `AGENT_BUSY` 串行化规则冲突，需要先冻结验收口径；
4. 本轮真实联调脚本和证据仍位于未跟踪的 `output/`，尚不是可复跑的仓库资产。

因此前端工作分为“必须补齐的验收资产”“条件式产品体验改进”和“后端修复后的复验”，不得为了前后端任务数量对称而无依据改动生产代码。

## 3. 前端必须完成的改动

### FE-H2-01：固化可复跑的 Stage H 真实联调驱动（P1）

**问题：** 本轮脚本位于未跟踪的 `output/playwright/`，依赖现场 appData、临时端口和脚本内上下文，换机器后无法可靠复跑。

**实施要求：**

1. 把可复用逻辑迁入明确的真实联调目录，例如 `apps/desktop/scripts/integration/stage-h/`；不要把临时证据目录变成源码目录。
2. 后端 URL、隔离 appData、角色/会话 ID、测试标记和证据输出目录全部由参数或环境变量传入。
3. 禁止写死 token；只允许沿用 Electron Secret Store，或通过不回显的进程环境注入。
4. 每个场景输出一份脱敏 JSON 摘要，至少记录前端 commit、后端 build SHA、协议版本、场景 ID、开始/结束时间、检查项与结果。
5. 脚本异常、超时或清理失败必须非零退出；不能只打印 `passed: false` 后仍以成功退出。
6. 临时代理、端口转发和隔离 userData 必须有 `finally` 清理；正式后端进程仍由操作者控制，不由前端脚本擅自启停。
7. 为 runner 增加最小 README，区分“自动化回归”“需要后端 fixture”“人工 UI 观察”三类步骤。

**验收：** 在新隔离 userData 下，仅提供后端 URL 和既有凭据即可复跑；失败会返回非零；仓库中不出现 token、个人绝对路径或固定测试数据 ID。

### FE-H2-02：统一 generation 终态关联规则（P1）

**现场事实：** 真实 `generation.completed` 有稳定 `generationId`，但 `conversationId` 可以为空；`generation.started` 携带会话归属。最初的临时脚本若按 terminal 的 `conversationId` 等待会误判超时。

**实施要求：**

1. 真实联调 runner 必须以 `generationId` 关联 started、segments 和 terminal；会话归属来自 started 时冻结的映射。
2. 增加回归用例：completed 缺 `conversationId` 仍能结束正确 generation，不能落入当前活动会话推断。
3. 复核生产 `StreamAccumulator`/message store 已遵循该规则；若已有覆盖，只补测试，不重写实现。
4. 不要求后端为了测试方便给所有 segment/terminal 重复添加 `conversationId`，除非未来正式 wire contract 另行升级。

**验收：** A、B 两会话交错接收终态时，均按 generation 身份收口；terminal 缺 conversationId 不超时、不串会话。

### FE-H2-03：连接世代变化后的角色操作回归（P1）

**现场事实：** 在 A tail 完成后切换 B，临时脚本立即用旧调用上下文探测 reset，前端正确返回 `CHARACTER_CONNECTION_EPOCH_STALE`。这是 fail-closed 保护命中，不能直接认定为生产缺陷。

**实施要求：**

1. 保留 `CharacterService` 的 connection epoch 校验，不得通过忽略 stale 错误来让旧请求提交。
2. 增加回归：连接世代在角色 GET/reset 途中变化时，旧结果不写缓存、不更新公开状态。
3. runner 在会话切换或重连后必须重新读取 binding/state，再以新 `expectedStateVersion` 发起 reset；不得复用切换前对象。
4. 如果通过真实 UI 能稳定复现“没有重连却出现 stale”，再排查 epoch provider 是否被会话激活错误推进；未复现前不改生产逻辑。

**验收：** 旧世代请求安全失败；新世代重新读取后可正常操作；不会因自动重试把有副作用的 reset 重放两次。

### FE-H2-04：更新当前状态与验收记录（P1）

1. 本文作为第二轮后续整改入口；doc 16 指向本文并记录当前阻塞。
2. 后端完成 BE-H2-01/02 且最终复验后，再更新原 Stage H 联调清单对应条目和结果汇总。
3. 不删除第一轮失败证据；用带日期的新结论说明其已被哪次复验关闭。
4. 最终闭账记录必须写明真实前端 commit、后端 build SHA 和“是否使用数据库手工修补”。使用手工修补的结果不能关闭 H-44。

## 4. 条件式前端改进

### FE-H2-05：`AGENT_BUSY` 会话切换体验（P2，先复核后改）

当前行为已经满足安全性：后端拒绝激活时，前端继续停留在原会话，不乐观切换。需要复核 UI 是否已明确显示“角色正在完成本轮收尾，请稍后重试”。

- 若提示已明确：只补单测/真实联调断言，不改 UI。
- 若仍是笼统错误：为 `AGENT_BUSY` 增加可理解的提示和人工重试入口。
- 不做无限自动重试，不在用户离开页面后偷偷切换，也不把 `generation.completed` 当成后端已完全 idle。

这项不是 Stage H 的 P0 阻塞，不得抢在后端 fixture 修复之前扩大范围。

## 5. 后端修复后的前端复验

### FE-H2-R1：官方 pinned fixture 闭环（最终门禁）

必须严格使用后端正式命令，不得再手工改 Mongo 或重写 revision：

1. seed 前确认 active catalog 正常且不存在 `chr_stage_h_fixture`；
2. 执行官方 seed；
3. 通过真实 REST/Electron 读取 active catalog 和 fixture detail；
4. 将 Definition 从 revision 1 更新到 2；
5. pinned 会话生成仍使用 revision 1；follow_latest 会话生成使用 revision 2；
6. 执行官方 cleanup；
7. active/archived catalog、detail、revision repository、两个 instance 和两个 session 均无 fixture 残留；
8. cleanup 再执行一次仍成功，证明幂等。

任一步出现 `INTERNAL_ERROR`、孤儿 revision 或需要手工数据库修补，均判失败。

### FE-H2-R2：A/B tail 隔离（按冻结口径复验）

推荐采用“公共 API 强串行”口径：

1. A 收到 `generation.completed` 后立即请求激活 B；
2. A tail 未完成期间得到 retryable `AGENT_BUSY`，活动会话仍为 A；
3. tail lease 释放后激活 B 成功；
4. B 的 reflector/buffer/Prompt 不含 A 的唯一标记；
5. A、B 的 characterId/instanceId/revision 全程一致。

若后端坚持验收“tail 运行时已经切到 B”，必须由后端提供显式 opt-in 的受控 tail gate；前端 runner 只消费该夹具，不通过延时猜测竞争窗口。

## 6. 前端不应改动的内容

- 不改 `character-contract-v1`、`schemaHash` 或公开错误码来迁就坏 fixture。
- 不放宽 `createdBy` 枚举接受任意字符串。
- 不移除 connection epoch、revision、stateVersion 或角色 tuple 栅栏。
- 不为 V1 伪造第二用户/owner UI。
- 不恢复旧数据迁移；开发阶段继续按既定决策使用干净基线。
- 不把任务中心、阶段 8 发布或新的角色功能混入本整改批次。

## 7. 完成定义

前端侧只有同时满足以下条件才可关闭：

- FE-H2-01～04 完成；FE-H2-05 已明确“无需改”或已完成；
- 后端 BE-H2-01/02 已在新 build 生效；
- FE-H2-R1 无手工数据修补通过；
- FE-H2-R2 按双方冻结口径通过；
- Stage H 清单与 doc 16 更新为同一结论；
- 前端工作树不遗留临时 token、appData、代理配置或未说明的测试数据。
