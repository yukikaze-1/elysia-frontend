## 2. 逐项关键决策（都写进了代码注释，此处只记决策本身）

### ②-1 表格横向滚动
- **纯 CSS**（表格自身成为滚动容器）而非"包一层 div"：`utils/markdown.ts` 头注记录的正是上一轮刚拆掉的
  "UI 结构/CSS 类名渗进功能层"分工，且 `div` 本就在消毒白名单内，注入 wrapper 会与用户内容自带的 div 混为一谈。
- 判据落在**集成层**：happy-dom 不做布局，单测只能断言 CSS 文本（实现细节）；集成用例量的是
  「表盒是否超出消息列」「溢出内容滚动后是否可达」。
- 夹具构造过程本身有结论：**"看起来像宽表"的东西不构成判别面**——12 列 + 长 token 时表格被
  `word-break: break-word` 压回气泡宽度（395px）根本不需要滚动；24 列才真的溢出。

### ②-2 拖入聊天区
- 落区与覆盖层一起上移到聊天区根 `.cy-chat`；`CyChatInput` 只留粘贴与文件选择（三入口仍是同一条附件状态机）。
- `CyDropOverlay` 改成**纯展示**（`pointer-events: none`，无 emits）：覆盖层若接收 drag 事件就会成为拖拽目标，
  使父层按 dragenter/dragleave 配平算出的"仍在区域内"判断漂移（表现为覆盖层自己闪断）。

### ②-3 字体缩放
- **不用 Electron `setZoomFactor`**：整体 zoom 改的是 CSS px 视口，会牵动布局断点判定与 Live2D 画布取尺，
  属"改窗口几何"而不是"改字号"。
- 落地前的实测更正了台账措辞：`--cy-user-font-scale` **早已定义且已被 body 消费**，真实缺口是
  **没有赋值者** + 308 处组件字号用绝对 px token 覆盖了继承 ⇒ 只赋值视觉上几乎无效。
  故本项的实质是"让整条阶梯乘它"，并由源码门禁钉住（含"不得二次相乘"）。
- 范围取 **90–130%**（默认 100，步进 5）：唯一数值先例是非权威原型（90–115%），此处放宽上限是因为
  台账给的理由是"无障碍刚需"，而 115% 在 14px 基准上只有 +2px；上限的代价用"130% 下授权弹窗
  拒绝/允许按钮仍在视口内且命中测试拿到按钮自己"这条可访问性红线用例兜住。

### ②-4 重发 / 重新生成
- 把 doc 12 C-03 的验收原话当硬约束：**「重发同一请求不会创建两条用户消息」**。
  照搬 `send()`（总是先插 `local-*` 乐观气泡）会立刻违反它，故共用一条**不新增气泡**的发送路径。
- 三处 `clientRequestId` 语义各有依据：已确认消息重发**复用**原 id（doc 02 §19 幂等重试）、
  失败消息重发与重新生成**铸新** id（doc 02 §16.2）。
- 重新生成保留旧回复（新 responseId = doc 03 §7.2 意义上的新回复组）；原位替换会伪造
  "同一条回复被改写"的语义并与回放/缓存快照冲突。撤回/编辑属 doc 12 C-11，不在本轮。

### ②-5 右键菜单
- 新建通用 `CyContextMenu`（仓库首个）：**teleport 到 body** 以避免污染 `.cy-vlist-row` 的 perf-gate DOM 契约，
  `role=menu/menuitem` + 方向键/Home/End + Esc/点外部/滚动即关 + 按指针坐标定位并夹取到视口 + 关闭回焦。
- 菜单只暴露**已存在**的能力：会话=重命名/删除（PRD §6.3 清单；置顶/归档/分组是 P1 且 store 里 0 实现），
  消息=复制 + 重发/重生成（与操作行同一套可用性判据）。
- 「复制什么」的判据收敛到 `utils/message-copy.ts`（两个入口共用一份，防两份副本漂移）。

### ②-6 截图预览
- `capturePreview` 增**必需** `sourceName`（取自**枚举快照**，与用户在网格里点的那个源逐字一致）+
  可选 `width/height/bytes`；提醒段排在「确认上传」**之前**。
- 记录一个**结构性事实**（不是取舍）：权限窗出现在源枚举之前，那一刻还不存在"所选屏幕或窗口"，
  因此"显示所选屏/窗"只可能在预览步骤满足——没有去改权限窗时序。

### ②-7 VAD / 静音结束
- 判据做成纯类 `SilenceTracker`（逐帧 RMS，阈值固定 −40dBFS）：真实麦克风在 CI 上不可控，
  判据必须是可确定性单测的纯逻辑；阈值是裸 RMS 数字，**不作为设置项**（对用户无解释语义）。
- 用**已有** PCM 帧算 RMS（`consumeChunk` 内顺手算），不额外挂 AnalyserNode、不动 worklet 热路径。
- 默认**关闭**：它会改变"什么时候停止录音"，不替用户决定；到点走与手动停止完全相同的路径并有可见提示。

## 3. 刻意没做的四件事（与理由）

1. **doc 11 §3.3「输入语言或自动识别」**：wire 的 `voice.record.start` 只有 `{recordingId, audio?}`，
   没有任何 language 字段。做一个不抵达后端的下拉框等于假装交付 ⇒ 不做，待后端支持后另立。
2. **doc 03 §5.1 里"消息右键 Edit 菜单"的两种读法**：评审记的是"标准 Edit 菜单／Main 原生 context-menu handler"，
   doc 03 §7.5 P1 记的是"编辑已发送消息并重新生成"——**两者都没做**。前者要解决的问题（正文可选中 + 复制）
   已由 H-02 解决；后者属 P1 且数据层不存在消息编辑契约。本轮做的是 DOM 右键菜单 + §7.5 已列动作。
3. **doc 03 §12.4 同句里的「代码字体大小／强调色／主题或跟随系统」**：本轮只做"全局字体缩放"。
   因此 doc 03 §15「Live2D、字体和强调色调整可以即时预览」与 doc 11 §10 同名条目**仍不可满足**
   （强调色未实现）——已在两处注记里写明，不当作已交付。
4. **doc 04 §8.4 落地注记称 result 含 `{sourceId, sourceName, size, mimeType, url}`**，而代码只回传
   `attachments`（尺寸/格式未进结果）。本轮未动，已记入 doc 16 台账该行，属独立项。

## 4. 过程中的真实缺陷、事故与教训（如实记录）

### 4.1 既有门禁抓到一个**真缺陷**（本轮最有价值的发现）
给 `VoiceSettingsSchema` 加字段级 `.default()`（旧文件兼容所必需）后，`SettingsPatchSchema` 里原来的
`VoiceSettingsSchema.partial()` **不会剥掉 default**：`{voice:{enabled:false}}` 这种单字段 patch 会被补上
`silenceAutoStop:false, silenceStopMs:2000` ⇒ 用户把静音时长调到 4s 后只要再拨一下语音总开关，
**4s 被静默改回 2s**。这正是 live2d/tools 早已踩过并规避的 IP-1 缺陷类。
是 `settings-tools.spec`（IP-1 用例）与 `voice-handlers.spec`（patch 原样入参）**当场变红**抓到的，
不是我复查出来的。已按先例拆出无默认的 `VoiceSettingsPatchSchema`。

### 4.2 CI 抓到我引入的回归
`e09f486` 之前的一轮 CI（run `34737645766`）红在 `electron-live2d.spec.ts` B4：
`expected '90%' to contain '1.50'`。根因是**我新增的字体大小滑杆**成了「外观与 Live2D」子页里的
第一个 `input[type=range]` / 第一个 `.cy-l2d-field-value`，而该用例用 `.first()` 与"首个命中的读数"取控件。
已改为按 `data-testid` 取（并在单测侧同步修掉同类位置假设）。**本地全绿不等于 CI 全绿**这条再次成立。

### 4.3 两处门禁/测试自身的 flake（不确定为回归，按性质修）
- `file-writer.spec.ts` 的「定时 flush」：CI run `34735704341` 的 windows job 红于 `expected '' to be 'line1\n'`
  （150ms 固定等待 + 一次性断言）。改为轮询到期限，**断言不变**。
- `temp-dirs.spec.ts` 的前缀扫描：全套并行时实测 6.6s > 默认 5000ms 而**超时失败**（单跑 88ms）。
  断言一字未改，只给这个纯 I/O 扫描用例显式 30s 预算。

### 4.4 我自己的事故：用 shell 读改写仓库文件，损坏了 8 个测试文件
批量补测试夹具字段时，我用 PowerShell `Get-Content -Raw` + `WriteAllText` 一次改写 8 个文件，
其中 7 个被整体改写（全文 diff）并出现真实内容损坏（`const`→`oonst`、`scripts`→`soripts`、
中文→乱码）。**这正是本仓库明文记录过、且我自己在 doc 16 里写过两次的纪律**：
"仓库文件一律不要用 shell 读改写"。处置：`git checkout` 还原 8 个文件，改用 `edit` 工具逐处重做，
并以 `git diff --numstat` 确认每处只有 1–2 行改动。**教训：批量机械改写不是例外**——
即便用 Node（UTF-8 安全）也只在"生成新文件"时可靠，**已存在文件的改写一律走编辑工具**。

### 4.5 三处"只在运行时暴露"的右键菜单问题（typecheck 与单测都不报）
1. **`v-for` 里的模板 ref 拿到的是数组** ⇒ `renameInput.value.focus is not a function`（渲染层 TypeError
   被 vue errorHandler 记录，界面只表现为"没聚焦"）。改用函数 ref 明确收单个元素。
2. **菜单项持焦点时被卸载 → 浏览器把焦点落到 body**，清掉调用方在同一拍设置的焦点。现关闭前主动 blur；
   且回焦**跳过 body/documentElement**（给它们 focus() 等于清空焦点）。
3. **聚焦时机不能用函数 ref 的挂载回调**（Vue 在 mountElement 里"先插入还是先 setRef"的次序不稳定，
   实测两次运行一次成一次不成）⇒ 改用 `flush: 'post'` 的 watch。
   （第 1、3 条都属于"看代码看不出来、必须在真实运行里才暴露"的类别。）

### 4.6 一处测试夹具的语义陷阱
`cy-conversation-list.spec.ts` 里给会话列表播数据时，profiles 模式会**拒收"缺角色绑定"的会话响应**，
列表渲染成空态 ⇒ 找不到 `.cy-conversation`。夹具必须带 `character` 快照（这不是本轮引入的规则，
而是既有校验在起作用）。
