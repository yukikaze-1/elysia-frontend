## 3. FE-S3-RUN2-P1-01：历史结果必须在模态框内部滚动

### 3.1 真实复现步骤

1. 在 Windows Electron 点击“聊天记录”；
2. 保持“全部会话 / 全部”并点击“搜索”；
3. 第一页成功渲染 50 条结果；
4. 尝试点击底部“加载更多”。

结果：按钮存在于 DOM，也处于 enabled 状态，但位于窗口可视范围之外。Playwright 的真实点击持续尝试滚动后仍报告 `element is outside of the viewport`；用户同样无法到达该按钮。

### 3.2 现场几何证据

第一页 50 条时：

| 元素 | top | bottom | height |
|---|---:|---:|---:|
| viewport | 0 | 721 | 721 |
| `.cy-history-overlay` | 36 | 721 | 685 |
| `.cy-history` | 60 | 5538 | 5478 |
| `.cy-history-results` | 215 | 5483 | 5268 |
| `.cy-history-footer` / `加载更多` | 5493 | 5523 | 30 |

通过 DOM 直接调用同一个按钮的 `click()` 后，第二页能正常返回并渲染到 100 条；此时：

- `.cy-history` 高度进一步增长到约 `10743px`；
- `加载更多` 的 top 约为 `10758px`；
- 第一页 50 行相对顺序仍全部保持；
- 页面无分页错误提示。

因此这不是按钮事件、IPC、后端 cursor 或排序问题，而是模态框与结果列表的高度/收缩/滚动约束没有生效。

### 3.3 代码位置与直接原因

文件：`apps/desktop/src/renderer/src/components/CyHistoryViewer.vue`

- `.cy-history-overlay` 使用固定覆盖层和 `display: grid; place-items: center`；
- `.cy-history` 虽声明 `display: flex; flex-direction: column; max-height: calc(100% - 48px)`，但实际 grid item 仍按内容最小高度被撑开；
- `.cy-history-results` 声明了 `overflow-y: auto`，却没有形成一个可收缩、占据剩余空间的 flex 滚动区，50 条结果直接贡献完整内容高度；
- footer 因而跟随结果内容落到视口外。

修复时应在真实布局中验证 grid item 与 flex child 的 `min-height`、`flex`、显式高度/最大高度及 overflow 组合；不要只在 jsdom 中断言 class 存在。

### 3.4 必须修改的行为

1. 历史查看器面板必须始终完整落在 overlay/viewport 内，不能由结果条数撑高；
2. header、筛选区、分类 tabs、状态区和 footer 保持可见，只有结果列表区域内部纵向滚动；
3. `加载更多` 必须能用真实鼠标点击，并可通过 Tab 焦点顺序到达；
4. 加载第二页时保留当前浏览锚点，不能因旧结果插入而把用户突然甩到列表另一端；
5. 保留现有按本地自然日分组、展示排序、`hitId` 去重和 opaque cursor 语义；
6. 兼容空结果、loading、loadingMore、错误重试和没有下一页时 footer 隐藏等既有状态；
7. 不修改后端分页大小或返回顺序来掩盖前端布局。

### 3.5 必须补充的测试

- Electron 集成测试准备至少 100 条历史结果，窗口使用本轮真实 viewport `1184 × 721`；
- 首次搜索后断言 50 条结果，同时断言 `.cy-history`、footer 和 `加载更多` 的 bounding box 均在 viewport 内；
- 使用 Playwright 普通 `locator.click()` 点击“加载更多”，禁止 `{ force: true }`、DOM `.click()` 或直接调用 store；
- 点击后断言渲染 100 条、100 个 `hitId` 唯一、第一页 50 条相对顺序不变；
- 结果区可滚动，header/footer 不随结果内容滚出面板；
- Tab 可到达“加载更多”，Esc/关闭按钮与焦点回归继续正常；
- 在项目支持的最小窗口尺寸再跑一档，防止只对当前 1184×721 特调。
