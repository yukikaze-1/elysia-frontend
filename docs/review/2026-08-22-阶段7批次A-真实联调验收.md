## 2. 联调发现与修复

首次联调按固定 CDP 端口启动时，Electron 实际开放了远程调试端口。根因是 `rejectForbiddenDebugSwitches()` 仅在 `app.isPackaged` 为真时执行拦截，开发态因此违背了页面“远程调试端口始终关闭”的承诺。

修复采用全构建统一策略：

- `findForbiddenDebugLaunch()` 集中检查 argv、Electron commandLine 与 `NODE_OPTIONS`，不接收 `isPackaged` 分支。
- 开发态、测试态、打包态统一拒绝固定远程调试端口和 Node inspector。
- 仅显式测试 harness 可放行随机端口 `=0`/pipe；固定端口即使在 harness 下仍拒绝。
- 新增策略单测，覆盖固定端口、`NODE_OPTIONS` 和 harness 边界。

修复后完整重启的真实应用无 CDP 监听，开发者模式重启复位也已在实际 UI 中确认。

## 3. Windows 测试隔离修复

联调前复核发现 Electron 43 在 Windows 上不保证通过 `APPDATA` 环境变量改写 `app.getPath('appData')`，既有集成测试可能触及真实 `%APPDATA%/Cyrene`。现改为 Main 在“未打包 + test mode + test harness”三重门下显式设置临时 appData，并由启动助手再次读回核对；任一条件不满足即 fail-closed。

隔离探针 1/1、批次 A Electron 集成 22/22 通过；修复验证期间真实用户目录关键文件的 SHA-256 与时间戳保持不变。
