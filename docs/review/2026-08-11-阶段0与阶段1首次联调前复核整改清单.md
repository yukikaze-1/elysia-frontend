## 4. P0：首次真实联调前必须修复

### FE-S1-P0-01：Windows 首次创建安全文件必然失败

#### 证据

`apps/desktop/src/main/persistence/safe-open.ts:78-80` 在 Windows 分支进入任何模式后，先执行：

```ts
const st = await lstat(filePath).catch(() => {
  throw new SafeOpenError(`${filePath} 无法检查`)
})
```

但新文件在 `mode: 'create'` 下本来就不存在。`lstat` 的 `ENOENT` 被提前转换成 `SafeOpenError`，后面的 `open(... O_CREAT | O_EXCL ...)` 永远不可达。

同一问题还影响 `mode: 'existing'`：新安装没有 `credentials.json` 时，Windows 分支丢掉原始 `ENOENT`；`CredentialStore.readFile()` 无法按“文件不存在”返回 `null`，`getStatus()` 会错误落到 `unavailable`，而不是正常的 `empty`。

#### 影响

- `credentials.json.tmp` 无法首建，Windows 上 Token 无法保存；
- app/audit writer 无法首建文件；
- 日志写失败被吞，表面上应用可能仍能启动，造成隐蔽失败；
- 阶段 1 明确要求 Windows 与 Ubuntu 各启动一次，而 Windows 从未跑过，现有 Linux 315/18 绿色测试无法覆盖该分支。

#### 必须修改

1. Windows `lstat` 必须区分模式和错误码：
   - `create + ENOENT`：允许继续进入 `O_CREAT | O_EXCL`；
   - `existing + ENOENT`：原样保留 `ENOENT`，供调用方识别“尚未创建”；
   - 文件已存在：拒绝 symlink/junction，并进入既有文件检查；
   - 其他错误：转换为安全公开错误。
2. `open()` 后统一 `fd.stat()`，并要求 `st.isFile()`；Windows/Posix 共用同一形态不变量。
3. 增加 Windows CI 或可注入的平台适配层测试，不能继续靠 Linux 上的 `process.platform` 分支测试冒充跨平台验证。

#### 验收测试

- Windows 干净 userData：`getCredentialStatus()` 返回 `empty` 或因系统 keystore 返回真实 `unavailable`，不能因文件缺失误报；
- Windows 首次 set Token 成功创建并可重启读取；
- Windows app.log/audit 文件能首建；
- Windows 既有 symlink/junction、目录、设备形态被拒绝；
- Windows 本机至少完成一次启动 → 设置 Token → 关闭 → 重启 → status 可用的冒烟。

### FE-S1-P0-02：开发 Renderer URL 的信任范围过宽

#### 证据

- `config/env.ts:34-48`：未打包时，任何可解析的 `http:` 或 `https:` URL 都让 `shouldUseViteDevServer()` 返回 true；
- `windows/main-window.ts:78-79`：该 URL 被直接加载进带 Preload 的主窗口；
- `ipc/registry.ts:11-15`：Main 只认“是不是主窗口的 WebContents”，不认该窗口当前到底加载了什么来源；
- 开发态 `renderer/index.html` meta CSP 没有 `frame-src 'none'`、`frame-ancestors 'none'`、`form-action 'none'`，并且 `connect-src 'self' ws: wss:` 允许连接任意 WebSocket Origin；
- 本轮故障注入已经证明，被替换的 HTTP 页面获得全部 18 个 Desktop API 并可成功 invoke Main。

阶段 1 设计文档把它记录成“仅 dev/test 形态的诚实边界”，但第一次真实联调通常正是在 `pnpm dev` 下使用真实 Token；因此它不能继续只作为已接受限制。更重要的是，阶段 2 当前允许 Renderer 传任意 `serverUrl`，Main 会读取已保存 Token 并用于连接。两项组合后，恶意 Renderer 不需要读回 Token，也能让 Main 把 Token 发到攻击者地址。

#### 必须修改

1. `ELECTRON_RENDERER_URL` 只允许明确的回环开发 Origin：`localhost`、`127.0.0.0/8`、`[::1]`；拒绝远程 host、userinfo、fragment，协议按实际开发需要收紧到 `http:`。
2. 把“受信 Renderer URL”做成 Main 的单一策略函数，窗口加载、导航和 IPC 来源校验共用，避免三个位置各自判断。
3. IPC 至少校验：
   - `event.sender === mainWindow.webContents`；
   - `event.senderFrame === mainWindow.webContents.mainFrame`；
   - main frame 当前 URL 符合 `cyrene://renderer` 或已批准的回环 dev Origin。
4. 开发态 meta CSP 补齐 `frame-src 'none'`、`frame-ancestors 'none'`、`form-action 'none'`；HMR 的 WebSocket 只放行已批准的回环 dev Origin，不能继续用 `ws:`/`wss:` scheme source 放行所有 WebSocket。生产响应头仍保持更严格策略。
5. 同时修阶段 2 报告 FE-P0-01：Endpoint/Token Origin 绑定。只修本项不能阻止已经受信但发生 XSS 的 Renderer 指挥 Main 外传 Token。

#### 验收测试

- `ELECTRON_RENDERER_URL=https://example.test/`、局域网 IP、带 userinfo 的 URL 均拒绝启动或回退 `cyrene://`；
- electron-vite 正常回环 dev URL 能启动、HMR 正常；
- 非主 frame、错误 Origin、导航后旧 frame 的 IPC 全部拒绝；
- 开发页无法创建同源 iframe；
- 开发态尝试连接非受信 `ws://`/`wss://` Origin 时被 CSP 拒绝；
- 打包态仍恒走 `cyrene://`，现有 artifact smoke 不回归；
- 与阶段 2 FE-P0-01 联合测试：不受信页面不能让 Main 向任意地址携带 Token。

### FE-S0-P1-03：MockBackend 不是隔离、可重复的真实替身

#### 证据

- `MOCK_CONVERSATIONS` 是模块级可变数组；`renameConversation()` 直接修改其中对象，状态会跨 MockBackend 实例和测试泄漏；

- `deleteConversation()` 是 no-op；
- `activateConversation()` 不保存活动会话；

- 现有 `mock-replay.spec.ts` 只覆盖一次发送和静态列表，没有覆盖 CRUD 后再 list、两个实例隔离、两次发送 ID 唯一和并发回放。

#### 影响

Mock 可以让 UI 看起来“基本可用”，却掩盖阶段 2 已发现的连接后初始化、会话切换、并发 generation 和去重问题。它不阻断 RealBackend 本身，但会降低阶段 0 基线的可信度。

#### 必须修改

1. 每个 MockBackend 实例持有自己的深拷贝会话状态；
2. create/rename/delete/activate/list 形成一致、可观测的内存模型；
3. fixture 作为事件模板，每次 send 注入新的 request/generation/message/response/event ID；
4. 提供可注入 clock/ID factory，使测试确定性且不依赖 `Date.now()`；
5. 支持取消某一 generation，而不是 `clearTimers()` 取消全部回放；
6. 增加两次发送、并发发送、两个实例隔离、完整 CRUD 的单测。

### FE-S1-P1-01：审计服务没有业务生产者

1. 把最小、安全的审计接口注入凭据 handler，记录 set/clear 的 attempt/result/status-change 元数据；
2. Endpoint/Profile/Token 绑定修改也要审计，但不得写 Token、完整 query 或聊天正文；
3. 明确审计失败语义：若操作已经提交成功，不能再向 Renderer 假报“凭据保存失败”；若要求 fail-closed，应在副作用前验证审计可写并设计 intent/result 两阶段事件；
4. 添加真实应用装配测试：经 IPC set/clear 后，临时 `audit/` 中出现预期 JSONL；
5. 运行日志和安全审计不能互相替代，文档中分别说明用途。

### FE-S1-P1-02：安全文件层不拒绝 FIFO/device/socket

#### 证据

POSIX 分支打开既有文件后只检查权限位，没有执行 `st.isFile()`。FIFO 可以设置为 0600，且 `open(O_RDONLY)` 会在 `fstat()` 之前阻塞。Windows 分支同样没有普通文件判定。

#### 必须修改

1. 对既有路径先做不跟随的形态预检；POSIX 打开时加入 `O_NONBLOCK`，避免 FIFO 在 `fstat` 前挂住；
2. 打开后必须以 fd 为准执行 `st.isFile()`，拒绝 FIFO、socket、目录、block/char device；
3. create 冲突回退 existing 时执行同样规则；
4. 保留 `O_NOFOLLOW`、fd 权限检查和包含性检查；不要用仅路径 `stat()` 代替 fd 复核；
5. Linux 测试增加 FIFO、Unix socket、目录；Windows 增加目录/reparse point/设备边界测试。

#### 验收测试

- 0600 FIFO 立即失败，不能阻塞；
- 0600 Unix socket、目录和设备文件立即失败；
- 普通 0400 read / 0600 append 仍按既有策略工作；
- symlink、父目录逃逸测试不回归。

### FE-S1-P1-03：退出没有覆盖凭据队列，超时仍会与写入竞速

#### 证据

- `CredentialStore` 有私有串行 `queue`，但没有 `drain()/close()`；
- `main/index.ts` 的 before-quit 只传 `diagnostics.closeAll`；
- `shutdown.ts:25-27` 在 1.5 秒 timeout 赢得 race 后立即 `app.quit()`；仍在运行的 `finish()` 不会被取消，进程退出会直接终止它；
- 代码注释写“超时只放弃等待、不与在途写竞速”，这在进程退出语义下不成立。

#### 影响

用户保存或清除 Token 后立刻关窗时，凭据操作可能还在队列中，退出流程不会等它。原子 rename 能降低文件截断风险，但不能保证本次变更落盘。日志 close 超过 1.5 秒时也可能被进程中断。

#### 必须修改

1. CredentialStore 提供 `drain()/close()`：等待已接纳操作结束、拒绝新写、清除明文 cache；
2. 退出顺序至少为：停止接收新 IPC → drain 凭据 → 关闭 adapter/取消后台任务 → flush audit/log → quit；adapter 部分同时与阶段 2 报告合并处理；
3. hard timeout 可以保留以防永不退出，但必须把结果标记为 timed out，文档诚实写成“可能丢失最后一批写入”；
4. timeout timer 在正常 finish 后清理，避免残留计时器；
5. 启动失败若 diagnostics 已创建，不要直接 `app.exit()` 绕过 close；增加统一的 fatal shutdown 路径。

#### 验收测试

- 注入慢 CredentialStore 写，触发 quit 后必须在写完成后退出；
- 超时路径只调用一次 quit，并能识别 timed out；
- 正常完成后 timeout 不再触发；
- close 期间的新凭据写明确拒绝；
- 完成 IPC 响应后的凭据在重启后仍存在。

### FE-S1-P1-04：生产安全和 Windows 都没有持续门禁

#### 现状

- `.github/workflows/ci.yml` 只有 Ubuntu check/unit/integration；
- integration 使用 `electron-vite build --mode test`，`isPackaged=false`、DevTools 可用；
- 真正验证 `isPackaged=true`、菜单移除、调试开关拒绝和打包内容的是 `pnpm package` + `verify:artifact -- --smoke`，当前不在 CI；
- Windows 平台分支没有 CI，也没有本机验收证据；
- 本轮 Linux 打包和 smoke 虽通过，但只证明当前工作区，不构成后续提交的持续保证。

#### 必须修改

1. 增加 Linux artifact job：干净构建 `pnpm package`，再在 xvfb 下执行 `pnpm verify:artifact -- --smoke`；
2. 增加 Windows job，至少跑 install/typecheck/unit/build 和 Windows 专属 persistence tests；条件允许时启动 Electron 并完成 Token 生命周期冒烟；
3. 阶段 1 退出门槛中，Windows/Ubuntu 的证据必须记录 commit 和 CI run，而不是仅写“代码有平台分支”；
4. artifact job 先清理并重建 `out/dist`，避免验证旧产物；manifest 或报告记录应用 SHA。

### FE-S1-P2-02：可变 `EMPTY_FILE` 会污染后续多 key 凭据

`credential-store.ts:12` 定义模块级可变对象：

```ts
const EMPTY_FILE = { version: 1, keys: {} }
```

set/clear 在文件缺失或损坏时直接取得该对象并修改 `file.keys`。当前 allowlist 只有 `backend.token`，影响被同 key 覆盖掩盖；但设计已经预留 `model.*`。一旦进入多 key，另一个 Store/损坏重建可能把模块单例中残留的旧加密块写回新文件。

改成每次返回全新对象的工厂，并增加两个 Store、多 key、损坏重建互不污染测试。
