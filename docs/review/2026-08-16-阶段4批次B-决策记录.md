## 4. 关键决策 rationale（本批实现语义）

- **语音族错误路由（D-P15）**：`VOICE_ERROR_CODES` 为共享常量（`STT_UNAVAILABLE`/`STT_PROFILE_NOT_FOUND`/`VOICE_SESSION_CONFLICT`/`VOICE_SESSION_NOT_FOUND`/`VOICE_RECORDING_TOO_LONG`/`VOICE_RECORDING_NOT_FOUND`/`DICTATION_NOT_FOUND`/`PLAYBACK_NOT_FOUND`）。real-backend `handleErrorFrame` 对这类码**额外** emit `VoiceErrorEvent{code, message}`（经 mapper `stampEvent` 打 envelope），既有 `onError` 路径保留（日志/审计不丢）；connectionStore `setError` 对语音族码不展示全局连接错误横幅（语音错误经 `voice.error` 在语音 UI 展示）。`PLAYBACK_NOT_FOUND`（audio.cancel 竞态）前端良性忽略。**依赖面：** 字幕终态/错误展示依赖 real-backend emit `voice.error` + connectionStore 横幅抑制——两者缺一则语音错误要么丢失要么误当连接错误（spec §10 风险）。
- **后端 STT 一次性同意（D-P16）**：`voice.consentBackendStt` 默认 false；任一语音操作（record/realtime/dictation）若 STT 执行位置为 backend 且未同意 → 先弹「音频将发送至后端识别（本机不保留）」确认；接受 → 置位（持久化「不再提示」）+ 继续，拒绝 → 中止。consent 对话框于 CyChatInput 语音入口触发；设置子页测试麦克风同样经 consent 挂起（Task 14 修复：consent 挂起时 waitForRecording 不超时，confirmDispatching 在途信号判失败）。
- **录音字幕终态（D-P17）**：普通录音停止后 `record_pending` 态**等** `voice.transcript` 或 `voice.error`（后端 STT 超时/失败恒发 `error{STT_UNAVAILABLE}`），45s 兜底判「未识别」；此时仅允许丢弃/重录，`commitRecord` 门禁 `caption 非空`；600s 硬上限（与后端一致），300s 时 toast 提示接近上限。
- **单向 IPC 守卫（D-P18）**：`voice:audio-chunk` 走 `ipcMain.on`（fire-and-forget，不 invoke），经 registry `registerOneWayHandler`——回调内复用 `isTrustedSender`（`senderFrame===mainFrame` + 受信 URL 校验，FE-S1-P2-01）+ zod 校验载荷 `{ bytes: Uint8Array }`，`bytes.byteLength ≤ 1MiB`（= 后端 `MAX_CHUNK_BYTES`，超限丢弃 + warn），然后转发 `adapter.sendAudioBytes(bytes)`；**仓库零裸 `ipcMain.on`**（`ipc-security.spec.ts` desktopApi 白名单同步）。
- **麦克风权限（D-P7）**：`decideMicrophoneAllow`/`registerMicrophonePermission`（纯 Node 可单测）——仅 `media` 权限、非 video（含 `mediaTypes` 数组判别）、requesting origin/URL 为受信 renderer（复用 `isAppRendererUrl`，不新建谓词）；非受信 origin 一律 deny。
- **控制帧先于采集（D-P19）**：三模式均先 `api.voiceStart*`（await 成功）再 `PcmCapture.start`，防采集 chunk 早于后端会话建立被 `sendAudioBytes` 丢弃。
- **TTS 播放（D-P8/D-P9）**：整段缓冲（`audio_start` → `audio_end` 收齐后播）；Main 解码 base64 → `getTtsMedia()` sink → MediaService `tts-live`（TTL 5min）→ `audio.session.ready{streamId, url}`；Renderer `<audio>` cyrene:// URL，`onended`/`onerror` 均清态（mock 404 走 onerror 防播放态卡死）；新 `audio_start` 到达即 supersede 旧 stream（后端中断语义）。

### 10.2 跨仓依赖与契约

- **BE-S4-RUN-P0-01（配套后端，in flight）**：`voice.discard{recordingId}` 统一定义为「不转写、不提交、不生成用户消息的取消操作」——RECORDING/TRANSCRIBING/PENDING 匹配当前录音 → 清态回 IDLE 成功；IDLE 迟到/重复 discard → **幂等成功**、不发 `VOICE_RECORDING_NOT_FOUND`；另一普通录音 mismatch → 拒绝不误清；realtime/dictation 活跃 → 明确错误不动其会话。wire schema 无新增字段（状态机语义修订）。前端代码按冻结契约开发，最终复跑用配套后端修复 SHA。
- **漂移 canary 是测试能力不是生产兜底**：前端在无 discard ACK（wire send-only）下无法区分「已接受」与「已拒绝」；契约漂移靠 real-backend 协议桩测试的 canary 用例暴露（桩配置旧契约「RECORDING 态 discard 拒 CONTRACT_VALIDATION」→ 断言收到错误帧 + 下一次 start 触发 `VOICE_SESSION_CONFLICT`），不冒充「已发送 = 已取消」。
- **`voice.error` 消费门控不改变 D-P15 路由与日志/审计**：real-backend 侧对 `VOICE_ERROR_CODES` 的 emit 不变；recording 态丢弃仅收窄 Renderer 消费面，防旧会话迟到错误污染新录音展示。
